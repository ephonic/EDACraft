# M117：消除已证明单驱动网线的驱动副本维护

实现冻结：`c2d18aaf77094b01a1c8525677d901de73f21f6c`。默认采用；生成模型可用 `-DDSIM_REFERENCE_STATIC_NET_DRIVES=1` 恢复通用驱动路径。M118 仅修正缺少源模块的诊断，四个性能程序的生成代码保持逐字节相同。

## 实现与边界

CPU 的 M116 Callgrind 中，`drive_planes` 及其 vector 操作约占 13% 指令。即使只有一个已知驱动，通用路径仍检查连接、别名、驱动 ID、溢出映射，并保存一份驱动值后再调用 `set_planes`。编译器现在在 `Instruction` 保留立即整网驱动的目标/RHS；完成全程序 lowering 后，用结构化写入范围、声明初始化和位连接证明是否仅有这一处驱动。符合条件的调用直接使用原 `set`，不再维护不会被读取的驱动副本。

多写入、部分/拼接写入、位连接、多驱动以及对应延迟驱动不参与此替换。门级/混合门级、并行 lowering（包括单域回退）、force/release、动态 fork、宽值和字符串设计保持原路径。普通信号发布、四态、订阅顺序、队列、PC、逻辑预算与观察者路径不变；快照只需要保存仍可观察的信号值。优化没有合并组合过程，也没有减少 Active/NBA 调度次数，不能据此声称已实现 P2 区域融合。

四个完整负载的替换点分别为 CPU 63、CRC 9、muldiv 20、AXI4 33。`--emit-ir` 新增 `static_net_drives` 和 `static_net_drive_signals`，可直接核查证明覆盖范围；不从生成的 C++ 文本反推语义。

## 完整性能验收

103 服务器、同一 GCC 11.5 `-std=c++17 -O2 -pthread`、CPU 0；所有编译先结束，再执行一次预热和三轮换序测量。原始工作量与端到端校验不变，48 份完整输出/计时记录全部核对通过。关闭优化的四个 `.text` 均逐字节等于冻结 M114。独立重读记录的结果见 `audit.json`，全部样本见 `measurement.json`。

| CPU | 14.62 | 13.06 | 10.7% | 5.70 | 2.29 |

对应 M114→M117 墙钟中位数为 CPU 14.69→13.10s、CRC 4.41→4.35s、muldiv 10.30→10.13s。VCS 墙钟有明显抢占（8.51/9.68/11.67s），不能把这些墙钟比值解释为模拟器内核效率。共享服务器的频率/负载仍会变化，本表只报告本次完整换序测量，没有挑选历史最有利数据。

固定 200000000 tick 前缀只用于指令分析，不能替代完整负载 runtime：CPU 429224823→375156741（−12.6%）、CRC 82225693→80408787（−2.2%）、muldiv 91581031→83997219（−8.3%）。前后逻辑步数与全信号哈希相同，详见 `profile.json`。muldiv 的前缀指令降幅没有等比例转化为完整运行时间收益。

## 功能与发布

`tests/static_net_drives`：30 份完整 ordered/settled 波形（额外核对跨信号变化顺序），789 个精确预算/完整信号状态比较，6 次预测接受/拒绝；包括 64 位 X/Z、反馈、多驱动、部分写、拼接、延迟、位别名、端口、force/release、宽值与并行回退。三个同源 VCS 用例的完整 TRACE 和静态 numeric bit 时间线一致，未改写测试源。ASan+UBSan 三个生成程序通过。扩大 NBA、条件事件、并发断言及组合部分写回归通过。

Mac/Linux 均通过不可变源快照构建、解析器检查和受影响回归后发布；两个安装入口分别重新生成并完整运行四个性能负载，源码哈希等于测量对象。后续 M118 发布保留相同运行时与代码生成。发布、安装、功能结果见同目录 JSON。原始输出、VCD、生成 C++、profiles、计时及源文件清单保存在两端 `dsim-test/evidence/m117-static-net-drives/` 或 `/apps/EDAs/own/dsim/evidence/m117-static-net-drives/`，不包含执行文件或 VCS 私有生成代码。

CPU 仍有约 2.29 倍的 CPU 时间差距。本轮收益来自消除静态可证明多余的驱动工作；后续仍须在可观察事件边界内减少组合中间更新和过程执行。
