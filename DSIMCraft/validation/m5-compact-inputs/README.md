# SDF INTERCONNECT 紧凑接收端

候选实现将私有接收端从通用 Signal 改为 compact 槽，并消除延迟驱动注册时的强制 fallback。保留旧接收端时间零的 Z→X 路径戳，继续使用原输入延时进程、事件队列、取消策略、路径选择与检查。说明见 [实现边界](../../docs/compact-interconnect.md)。

冻结候选源码共 410 文件；相对前一批只改运行时、门级代码生成、CMake 和延迟驱动测试，增加一个生成程序对照入口。RTL/gate parser、SDF parser、Liberty、DWF 编解码器均未改。原始网表、1.2GB Liberty、完整 SDF、宽测试平台和生成的 111 种功能模型保持原样。

两平台各 57/57 完整回归通过。五组生成程序的 generic/compact 完整 stdout 和 ordered/settled VCD/DWF 对照通过，含多驱动、窄脉冲、逐接收延时、输入输出串联及路径/检查组合。通用与 compact 两版延迟驱动内核覆盖四态、64 位通用值、异步零延时、Active/NBA/FIFO、取消、alias、重复检查点及预测隔离；实际 compact 内核与生成的组合回滚程序执行 ASan/UBSan，通过完整波形。Linux sanitizer 库不可用的既有边界不变，不宣称远端 sanitizer 通过。

全量真实 C++ 与前一批实际执行版本逐字核对，仅有两处预期变更；覆盖 790,222 INTERCONNECT、867,982 IOPATH、86,496 检查，没有关闭检查。非负模式的 23,051 个负 limit 更新仍夹零，VCS 同样报告 23,051 NNTC 注解错误/0 warnings；不称为零错误注解或完整负检查模式。

真实零延迟和 100k FF 反馈的实际新旧编译器产物经同机 C++ 预处理后逐字相同，记录在 `zero-identity.json`，不会以新测量噪声宣称这两类负载获得收益。统一五模式在 macOS 原生和 Linux 新编译 VCS 差分通过。

完整 SDF 运行测量：原始 300,909 单元、原 256/257 位 TB、128 笔输出，固定 CPU0，旧版/compact/VCS 各一次预热，随后五轮交替运行。每次核对全部输出，保留进程 CPU、墙钟、RSS、负检查注解和主机负载。VCS 程序来自前一批同模型新编译产物，本轮重新执行；功能小例的 VCS 为本批新编译。VCS 启动时加载已有二进制 SDF 缓存，该成本包含在进程计时，首次文本 SDF 转换不属于本次重复运行；dsim 编译时回标成本单独记录。共享主机、未锁频率，不外推 RTL/零延迟/波形/并行。

初次计时脚本误以为 VCS 重复运行会重写注解日志，只有一次 VCS 预热完成后采集失败，保留于 performance-log-path-failure；未开始 native 测量。已核对 simv.daidir 的二进制 SDF 缓存和前次完整注解，修正后另开 performance/ 预热与五轮测量；每次 VCS 运行核对缓存未变，缓存也纳入归档。
