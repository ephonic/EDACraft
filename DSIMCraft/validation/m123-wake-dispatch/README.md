# M123：孤立唤醒与进程执行合并

普通 RTL 的定时或 #0 唤醒此前经过 wake 出队、执行事件入队、执行事件再次出队。Active 只剩该唤醒时，直接完成第二次逻辑调度并执行；省去一次物理入队和出队。逻辑步数保留，预算不足仍入队并在原边界抛异常，检查点和恢复执行保持一致。

进程已经排队、Active 仍有其他事件时保留原路径；门级时序、取消、并行、Reactive 配置也保留原路径，避免越过额外的每轮检查。`DSIM_REFERENCE_WAKE_DISPATCH=1` 独立关闭优化。

103 服务器 GCC 11.5，`-std=c++17 -O2 -pthread`，CPU0；原始四个负载及输入不变，先编译全部程序，再一次预热、三轮换序。基线为冻结 M122。

同一200000000 tick前缀的逻辑步数/全信号位哈希保持一致。诊断统计独立于计时，Ready push/pop 各减少 CPU 60000、CRC 40002、muldiv 40002，分别约5.90%/21.66%/18.03%，每一项都严格等于实际合并次数。AXI4 没有历史前缀文件，仅比较本轮默认/关闭优化的相同前缀，不把它标成跨历史版本证明。见 `scheduling-stats.json`。

新增测试包括512个预算中断后状态及检查点/预测恢复比较、197个生成模型精确预算比较、10份 ordered/settled 波形及预测结果。默认与关闭优化、时间轮要求完整波形记录一致；真实两分区并行的声明顺序与无关进程交错可不同，因此按层次信号名比较每条完整时间线。原始同源 VCS 测试逐行比较7行 TRACE，包含 #0、NBA、延迟NBA和定时事件。

ASan/UBSan 新内核通过。诊断计数器随后补入头文件，未启用统计的最终生成代码与实测程序 `.text/.rodata/.data` 逐字节一致，`final-code.json` 同时保留实测及最终 CPP 哈希；不把源码哈希变化冒充重新计时。两端稳定版发布前运行相关回归，发布后重新生成并完整运行四个原始负载。
