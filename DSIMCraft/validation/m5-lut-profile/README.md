# 已采用 LUT 后端的真实活动前缀 profile

保留全部真实 300,909 单元及完整原始生成代码，只把运行终点改为 300ns（全局 tick 1ps）。正常程序与 Callgrind 程序均核对同一前六组完整 golden，没有缩减设计或替换逻辑。源码来自已采用四态 LUT 的冻结生成源；本批 SDF 接入关闭时，非 SDF 生成主体及 runtime 宏关闭预处理等价性另行验证。

GCC 11.5，C++17 O2 / g1；Callgrind 3.26.0，记录 Ir。总计 **3,702,225,314** 条指令，包含完整设计初始化和活动前缀，不是孤立稳态测量。按函数聚合各源文件的 self Ir（不含自动源注释里的调用子项，避免重复计数）：

| 函数 | self Ir 占总计 |
|---|---:|
| publish_compact | 15.42% |
| drive | 13.58% |
| run_to | 10.90% |
| gate_eval_12 | 7.81% |
| 组合求值共享回调 | 6.76% |
| ReadyQueue::push | 6.09% |

这些是指令归因，不是 CPU 百分比，也不是新加速比。原始 Callgrind 的 brk segment overflow 工具警告完整保留；正常/插桩输出一致。分配器与初始化也在采样范围中，不能将该表直接等同实际运行时间分布。

下一候选为把 ReadyQueue 扩容的冷路径移出入队快路径，保持环形 FIFO 状态、增长/复制、事件顺序和检查点布局；只在隔离生成源中试验，以完整真实设计和反馈配对 CPU 决定下一步。

`profile-verified/` 保留源、实际二进制、完整原始 Callgrind、注释输出和所有日志。`verify.py` 对照另一份已冻结源，严格核对只替换运行终点、六组 golden、源码/二进制 SHA 和原始 Ir；`analysis.json` 保存归档哈希、逐文件身份和函数统计。
