# M133: module/interface header imports and named module ports

This functional change resolves explicit/wildcard package imports before module/interface parameter defaults and port declarations. Each elaborated clone owns its header import AST and lexical binding. Package storage remains canonical and shared. Named ordinary module ports reuse existing typedef resolution, preserving width, signing, two-state conversion, enum identity and packed aggregate metadata. The gate parser and runtime are unchanged; there is no new performance claim.

Six fixtures exercise ANSI/non-ANSI headers, module attributes, multiple import statements/items, typed parameter defaults, named/positional overrides evaluated in the caller scope, repeated/generate clones, interface/modport aliases, shared package state/NBA, grouped typed ports, explicit var, signed arithmetic, two-state conversion, enum/struct ports, wildcard shadowing and duplicate imports. Each platform's regression compares 26 complete ordered captures across serial/time-wheel/threaded modes and accepted/rejected prediction replay; 15 invalid cases check diagnostics and absence of generated code. A repeated parser cleanup test checks separate import nodes, parent pointers, widths and canonical shared symbols over five parses. Threaded mode does not imply that these shared-state designs run in multiple partitions.
