# 当前 dsim 与 VCS：功能与性能对照

功能推进到 [M53](../m53-fork-control/README.md) 的 join_any/join_none、wait/disable fork 静态子集。尚不支持重叠动态激活或 automatic 父帧逃逸；历史测速仍不代表当前代码，本批未重新测速。

功能实现已推进到 M52 的词法命名块 disable、并发后代与 automatic task 多活跃调用取消、关闭标签；见 [M52](../m52-named-disable/README.md)。M51 的 fork/join 与 M50 的非阻塞内部事件赋值也已接通。下文性能仍为 M22 和历史门级/SDF 冻结版本数据，尚无当前 M52 同口径重测；旧批次边界按各批记录理解。

M42新增动态前缀子数组过程复制和delay函数调用，关闭M41的动态子数组拒绝差异；VCS逐元素重复索引/delay函数调用及阻塞赋值内delay等差异仍保留，见 [证据](../m42-dynamic-array-copy/README.md)。未重新测速。

M41 新增静态数组整体过程复制，VCS共同源对照及阻塞赋值内delay差异见 [证据](../m41-array-copy/README.md)。本批未测速，历史速度数据不代表当前源码。

M40 新增静态 wire/tri 数组与电气合并端口，功能对照见 [证据](../m40-net-arrays/README.md)。本批未测速，下文历史速度数据不代表 M40 当前源码。

M39 补齐静态变量数组input/output、整数组/静态子数组、逐维声明顺序映射和同宽两态转换，修复宽数组元素的延迟分类。原始VCS共同源、全部数组packed观察映射和边界探针见 [M39](../m39-array-ports/README.md)。一般net/复合类型数组端口、ref和数组形参仍缺，本轮未测速。

M38 补齐显式变量连续 assign、静态目标/混合拼接及单值惯性 delay，接入已有波形、时间轮、并行和回滚；写冲突采用区间扫描。实际 VCS 同源验证及无延迟重复变量左值差异见 [M38](../m38-variable-assign/README.md)。动态连续左值、数组端口和完整事件区域仍缺，本轮没有新性能测量。

M37 补齐模块 output 到父级变量及静态位段/数组字/成员、混合拼接、驱动冲突检查和延迟 NBA 传播；实际 VCS 对照范围与原始边界探针见 [M37](../m37-variable-ports/README.md)。M37 当时尚缺显式变量 continuous assign，现见 M38；数组端口/ref 等仍缺。本批没有新性能测量。

M36 补齐枚举数值遍历方法 first/last/next/prev/num；原始 VCS 无类型 parameter、标签宽度查询及编译标志相关的接收者副作用差异保留，五种方法的已测表达式路径与完整字符串/验证语言能力分列，见 [M36](../m36-enum-methods/README.md)。本批没有新性能测量。

M35 增加 unique/unique0/priority if/case 和逐过程延后报告。六组共同源 756 位时间线相同，告警 native 12 / VCS 15，有三个明确差异；另保留函数条件被 VCS IUC 忽略的探针，详见 [M35](../m35-selection-checks/README.md)。本批没有新性能测量。

M34 补齐静态多维数组：六例实际 VCS 共同源自检及 1544 位直接导出、660 位数组 packed 观察时间线通过。多维声明顺序、宽/未知/越界下标、逐维副作用、foreach、delay/NBA、automatic 和双线程均纳入回归，范围及证据见 [M34](../m34-multidim-arrays/README.md)。本批未重新测量性能，M22/历史门级数字不能当作 M34 测速。

日期：2026-10-20。dsim 生产 CLI 仍报告 0.13.0。功能已更新至 M39 的静态变量数组端口及 M38 的显式变量连续赋值及 M37 的模块变量输出连接；此前 [M36](../m36-enum-methods/README.md) 的枚举数值方法、[M35](../m35-selection-checks/README.md) 的限定选择检查、[M34](../m34-multidim-arrays/README.md) 的静态多维数组以及 [M33](../m33-foreach/README.md) 的静态 foreach、多索引/跳维、只读自动索引及延时/重叠任务隔离；此前 [M32](../m32-set-membership/README.md) 的整数/packed 集合匹配 inside、case inside 和通配相等 ==?/!=?；此前 [M31](../m31-automatic-subroutines/README.md) 已支持非递归 automatic 函数/任务、入口初始化、跨 delay/event 激活隔离及挂起期间回滚，[M30](../m30-call-arguments/README.md) 已支持默认/命名/空实参与入口事件初始化对齐。性能仍对应 M22 的 595 文件冻结源码，M23–M39 功能更新后未重新测速，不能只用版本字符串区分。对照工具为服务器 10.131.254.103 的 VCS W-2024.09，source /apps/EDAs/syn.bash。商业 VCS 的广泛 SystemVerilog、原生验证环境、覆盖分析及 Verdi 集成能力见 [Synopsys 官方说明](https://www.synopsys.com/verification/simulation/vcs.html)；不据此宣称该安装版本完整实现最新语言标准。

当前结论：功能仍是可执行并经过差分验证的子集。M22 实测简单时钟/扇出 CPU 为 VCS 的约 1.13/1.02 倍，但整数长循环为 12.35 倍；历史真实全 SDF 最近一轮为 7.67 倍。不能宣称整体接近 VCS，当前性能重点至少包括算术代码生成和 SDF 中间事件传播两条线。

| 能力 | 当前 dsim 的已实现范围 | 主要差距 |
|---|---|---|
| RTL 编译仿真 | C++ 编译执行、四态/多字、signed/两态整数、类型化值参数、generate、常见 always/循环、静态和非递归 automatic 函数/任务及 output/inout/void/默认与命名实参、整数/enum/packed struct/union typedef、命名类型值参数和子程序签名、数组查询与位向量系统函数、命名/尺寸 cast | 类型参数、命名类型模块端口、package/interface、复杂数组、ref/递归/完整常量函数、动态激活及层次能力未齐 |
| 验证语言 | 静态 foreach（多个/省略索引、只读自动索引及延时回放），普通立即 assert/assume/cover 条件与动作，severity 诊断，自检脚本，整数/packed inside、case inside 和通配相等，动态闭区间/单维数组成员 | 无并发 SVA/property/sequence、clocking、class/约束随机化/UVM、覆盖数据库；集合匹配仍缺复杂数组/非整数/开放范围，cover 动作不等于完整覆盖率 |
| 门级模型 | 独立紧凑 parser、Liberty 组合/三态/理想 ff/latch；真实 300,909 单元设计已跑通 | 不能直接替代任意厂商标准单元 Verilog、UDP、完整 specify/强度语义 |
| 延迟和时序 | RTL delay/event/NBA、编译式 SDF IOPATH/INTERCONNECT、有限 PORT/DEVICE/条件路径和常见 timing checks | 完整脉冲/取消、一般条件、notifier、负检查延迟信号及完整事件区尚缺；默认非负检查模式有边界 |
| 波形与调试 | 原生 VCD、DWF 四态/多字编码与块 Zstd 压缩、索引/CRC/恢复、输出事务 | 尚无与商业波形/Verdi 调试生态相当的互操作、GUI 和完整验证追踪 |
| 并行/回滚 | 独立 RTL 域线程执行、保守通道、检查点/失败预测回放、打印与波形事务 | 无通用自动预测器、增量回滚和复杂门级时序安全切分；已有 API 不代表自动提速 |

上述 dsim 范围来自当前实现与定向验证，不是按用例数计算的“VCS 功能覆盖率”。历史 [M33 验收](../m33-foreach/README.md) 六例924条VCS导出物理位时间线一致，29位未导出数组字另有独立完整预期；仅一个共享静态局部变量做明确作用域名称对应。验证74次捕获、2次遍历挂起期间回放、25类拒绝及真实双线程。普通for隐式计数器导出仍有既有差异，原始双方波形保留。此前 [M32 验收](../m32-set-membership/README.md) 六例全部968条VCS导出物理位时间线一致，无名称映射；另有VCS未导出的96位数组字按独立逐时刻预期核验，不计入VCS一致位数。验证74次捕获、2次失败预测回放和真实双线程。当前编译器重跑的 [M31](../m31-automatic-subroutines/README.md) 六例1272条导出位时间线仍一致，无位排除或名称映射；[M30](../m30-call-arguments/README.md) 六例2993条仍一致，无位排除，仅两个generate返回变量做明确名称对应。原 M29 初始化差异探针的256位也已对齐。此前 [M22](../m22-explicit-casts/README.md) 为五例2214位；每批一致性仅覆盖各自共同输入，不代表任意 SV 行为相同。

性能必须按场景分开看。历史同轮实测如下，**不是本轮新测速**：

| 历史负载 | dsim CPU | 同轮 VCS CPU | dsim/VCS 耗时比 |
|---|---:|---:|---:|
| 300,909 单元真实网表，零延迟、128 笔、无波形，预热后五轮 | 12.38 s | 10.48 s | 1.18× |
| 原始完整 SDF，128 笔、无波形，M9 短筛选两轮中位数 | 69.415 s | 9.055 s | 7.67× |

第一行来源 [FIFO batch 验收](../m5-fifo-batch/README.md)，第二行来源 [M9 验收](../m9-timers-selects/README.md)。两行配置、工作量不同，不能互相相除，也不能代表整体 RTL、任意时序库或当前新测结果。SDF 使用受支持模型和默认非负检查边界，128 笔输出一致不等于时序行为全面兼容。

本报告 benchmark.py 使用 M22 Linux 实际编译器重新生成 RTL 程序，在同一主机固定同一逻辑 CPU、串行/无波形/无覆盖/无调试条件下比较。包括启动基线、LCG 算术循环、时钟/边沿/NBA、64 过程扇出，每种计算负载两个规模；独立数学预期核对全部 TRACE。每个工具预热一次，三轮交替执行，CPU（user+system）与墙钟分别记录，编译另计。VCS 使用 -no_save 消除 ASLR 导致的重新执行，保留其正常启动/初始化成本；共享机器未锁频率。

| 本轮 RTL 负载 | dsim CPU | VCS CPU | CPU 耗时比 | dsim 墙钟 | VCS 墙钟 |
|---|---:|---:|---:|---:|---:|
| 仅启动/退出 | <0.01 s | 0.73 s | — | 0.008 s | 3.388 s |
| 整数 LCG 2000 万次 | 0.91 s | 0.76 s | 1.20× | 0.927 s | 3.418 s |
| 整数 LCG 1 亿次 | 2.08 s | 0.55 s | 3.78× | 2.096 s | 2.386 s |
| 时钟/NBA 500 万周期 | 0.73 s | 1.04 s | 0.70× | 0.744 s | 3.845 s |
| 时钟/NBA 3000 万周期 | 4.40 s | 3.91 s | 1.13× | 4.424 s | 5.717 s |
| 64 过程扇出 ×100 万周期 | 2.71 s | 2.93 s | 0.92× | 2.732 s | 5.729 s |
| 64 过程扇出 ×300 万周期 | 8.10 s | 7.92 s | 1.02× | 8.137 s | 10.746 s |
| 整数 LCG 10 亿次（追加长测） | 20.99 s | 1.70 s | 12.35× | 21.068 s | 4.500 s |

CPU 比值大于 1 表示 dsim 耗时更多。启动用例的 dsim CPU 在 GNU time 的 0.01s 精度下为 0.00s，不能视为无开销；其墙钟为约 7.5ms，VCS 为约 3.39s。各进程 CPU 均包含初始化，短用例的 VCS 启动成本明显。两个算术规模的 VCS 总 CPU 随规模增大反而下降，短测存在明显变动，不适合差分估算每次运算成本；不做启动相减或用其墙钟优势宣称内核更快。追加 benchmark-long.py 的 10 亿次算术长测采用相同方法，并在首组全部完成后独立运行：dsim 三轮 CPU 20.94/21.36/20.99s，VCS 三轮均约 1.70s，中位数比 12.35×。它仍包含初始化，但比短测更能暴露算术密集负载差距。墙钟比约 4.68×，不能替代 CPU 比。

首组七个小型输入的单次编译墙钟 dsim 为 1.49–3.46s，VCS 为 6.46–8.75s；未覆盖大规模 RTL 编译。运行峰值 RSS 的三轮中位数 dsim 为 3072KiB，VCS 为 107068–112016KiB；它包含各自运行框架，不能推导大设计的内存比例。硬件为 Intel Xeon Platinum 8358 @2.60GHz，128 逻辑 CPU，运行固定 CPU0。源清单、编译器身份、全部输入及原始 .time/.log 留存在 linux/，核对脚本为 verify.py。8 个用例、64 份运行记录（含预热）的独立数学 TRACE 和原始 CPU 中位数全部核对通过，见 verification.json；这不是全内部事件流的等价证明。

缺少本轮大规模 RTL、当前源码真实门级/SDF、新旧版本配对，以及波形吞吐/压缩率/随机读延迟的同口径比较。现有数据足以定位后续重点，尚不足以给出通用“平均慢几倍”。

已有完整 SDF 剖析显示通知、驱动解析、输入通道、路径选择和定时队列存在大量工作。上述运行比较关闭波形并另计编译，因此 parser 和压缩格式不能解释这组运行阶段差距。过去局部队列/分派候选收益不稳定，持续缩小 SDF 差距需要减少中间事件和逐单元调度，同时保留四态、delta、反馈、多驱动、毛刺与时序弧观察边界；不能把输出稳态相同当作完整等价证明。详见 [差距证据](../../docs/performance-gap.md)。

当前长测生成代码可直接观察到：没有 delay/event 的 for 循环仍以条件、循环体、增量及回边四个 PC 状态执行，每个状态调用 step()，循环体使用通用 get/set 和四态 V 的乘加运算，见 linux/performance-long/arithmetic-1000000000/model.cpp。它为无挂起控制流直接生成本机循环、消除可证明无外部观察的中间存储和专用化整数算术提供了明确优化对象；尚无消融实验量化这些项各自贡献，不能直接把 12.35× 全归因到某一个函数。任何优化仍须保留未知态、可见副作用、事件预算、波形及回滚语义。
