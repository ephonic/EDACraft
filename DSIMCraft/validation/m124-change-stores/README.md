# M124 未采用的通知热路径实验

两个候选都没有进入默认代码和稳定发布。`rejected-lazy.patch` 为运行时延后边沿解码；`rejected-static.patch` 为编译期证明只有 change 订阅的单驱动网线生成专用 setter。补丁均相对 f730b62（M123），两份 runtime/compiler 源码已恢复至该版本。

| 完整负载 | 动态延后解码 Mac CPU 变化 | 静态 setter Mac CPU 变化 | 静态 setter Linux CPU 变化 |
| --- | ---: | ---: | ---: |
| CPU | +2.05% | -0.31% | -1.61% |
| CRC | +0.55% | -0.01% | +7.04% |
| muldiv | +1.95% | -1.53% | -0.83% |
| AXI4 | +4.10% | +2.69% | 0.00% |

正数为变慢，负数为耗时下降。每组一次预热、三轮换序，完整原始负载及输出不变。Mac 使用 clang C++17 O2；Linux 使用 GCC C++17 O2 pthread，固定 CPU25，参考为冻结 M123，另外运行原始 VCS。原始样本见三个 JSON，脚本见 measure*.py。Linux 早期受共享主机负载干扰而中止的试跑没有纳入此表；CPU25 正式测量已完整结束。

这些结果不支持默认启用专用 setter；主要热点需要从减少信号物化、通知和进程调度的次数处理，不能假定少一个边沿解码分支就会加速。

`rejected-*-tests` 只保存实验开发时的程序，未接入 CMake，也不代表完整验收：相对仓库路径需要恢复到原 tests 目录才可运行。动态版本曾通过四组语义检查；静态候选尚未完成六组综合语义回归。这里的完整负载输出一致也不等于全部调度语义已经验收。measure 脚本依赖私有 /tmp 中的冻结生成模型，回放前需恢复相应模型。
