# 组合求值按模型生成处理函数的隔离试验

候选直接基于已采用的紧凑网/驱动/LUT及有限SDF版本，不叠加未采用的监听或队列变换。默认编译器暂不改。

早期0.13.0已有每模型sample/commit/eval均专用化的失败试验，见validation/m5-model-handlers；该冻结记录不修改。本次只专用化组合eval，时序sample/commit完全保持当前实现，并在已采用LUT的新基线上重新测量，证据另存validation/m5-lut-model-handlers。LUT减少求值成本后是否使直接内联更有价值，仍须以新配对计时判断，不能把旧试验或新profile当收益证明。

新profile中共享组合处理函数self Ir约6.76%、gate_eval_12约7.81%；每次组合过程目前先读取cell.model再通过eval表间接调用模型求值。候选为每种组合模型注册独立compiled_handler，函数体直接调用对应gate_eval_N，让C++编译器能够内联；每个过程的payload仍是原cell索引。不改变process创建顺序/ID、cell引脚/输出求值/驱动顺序、监听、Active/Inactive/NBA或内部网事件。时序sample/commit与SDF路径处理保留原实现。代价包括更多处理函数、更复杂的间接分支目标、代码尺寸与编译成本，须实测。

预先声明：完整真实300,909-cell/128golden和100k触发器反馈；相同GCC11.5 C++17/O2、固定同核、各预热一次、五对交替，保存完整计时/输出/源/二进制及编译日志。真实配对CPU收益中位数≥3%、至少4/5改善，反馈中位数回退≤3%才进入独立7对真实/5对反馈复测；复测门槛≥3%、至少5/7真实改善，反馈回退≤3%。同一候选不择优删样本，不混合历史VCS分母；前一监听试验必须终止后才开始远程编译/计时。

若两阶段通过，仍需真实编译器接入并对实际生成代码验证、两平台完整功能/有序波形、SDF、预测回滚/提交、实际ASan/UBSan与同轮VCS计时后才能采用。稳态输出相同不构成删除初始或delta事件的许可。
