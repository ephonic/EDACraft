# 近时间队列候选

当前是独立开发候选，尚未替换生产运行时、没有 CLI 接入、没有 Linux 性能结论。由完整 SDF 诊断的约 5,071 万次堆插入和短交付延迟分布驱动：256 个近时间 FIFO 桶、占用位图和复用节点池，远时间保持 `(time,order)` 二叉堆；真实时间推进时迁移远事件，清除未来失效事件不推进时间。各结构均自有存储，可整体复制进检查点。

`preliminary-validation.json` 记录基于冻结 425 源 `909f7d2…` 的阶段性验证：

- 一百万次混合操作与标准堆逐次对照，含边界、同刻稳定顺序、迁移、取消和复制恢复；本地 ASan/UBSan 通过。
- 10 个实际运行时内核通过，4 个实际内核本地 ASan/UBSan 通过。
- 23 个实际生成程序的 138 份完整 ordered/settled × VCD/raw/Zstd 捕获与原队列一致，含预测失败重放。
- 实际完整原始 scalar SDF 程序仅替换整个 runtime 和增加队列宏，本地 Clang/O1 全部 128 笔输出匹配参考。

基线连续赋值在后续 VCS 验证中发现语义差异，正在 `m4-continuous-vcs` 修正。上述结果证明队列候选相对于该冻结基线的行为一致，不能替代修正版本的接入验收；候选须重放到修正后的源码，再进行两平台和独立性能验证。`queue-test.stderr` 保留最初测试夹具倒退时间的失败，随后修正夹具起点；未放宽队列拒绝时间倒退的规则。

`build_candidate.py` 只生成本目录下的 runtime；`timer_queue.hpp` 是组件原型，`kernels.py`、`waves.py`、`full_local.py` 是验证入口。性能实验不得与远端功能构建/测试并行。
