# M127：CPU 剩余差距与通用过程执行/传播开销

本轮完成热点定位和生成代码核对，没有修改生产调度器，也没有宣称新的加速。测量对象仍是已发布 M126 的 Intel `-O3 -fp-model=strict -xHost -ipo` 模型。M126 完整 CPU/VCS 耗时比约1.62，见 [完整负载](../m126-leaf-batch/linux-full.json)。用户要求优化应当泛化；以下所有设计判断依据语义和依赖关系，不以模块名、CPU 指令、程序内容或测试校验和作为优化条件。

**当前证据支持优先优化 RTL/TB 共用的过程执行与信号传播，不能把主要差距直接称为 testbench 本身的调度。** TB 的时钟/激励两个闭包自身仅占原生采样约2.64%；这不包含它们调用的共享运行时以及触发的下游 RTL，不能当成 TB 的总成本。相应地，不能从这个数字断言所有 TB 优化最多只能节省2.64%。

## 当前原生热点

在103的CPU25，对冻结 DSIM/VCS 原生程序分别做一次完整对照运行和三轮换序采样。六次采样及两次对照均完整执行原始7500006周期负载，检查完整 PERF 结果；代码、参数和工作量没有改变。用 ITIMER_PROF 记录 RIP，退出后按 ELF 映射和符号解析，DSIM共28252个样本，VCS共17005个样本。采样时间不用于发布新的速度数字，也不是 PMU 周期测量。

## 实际 VCS 默认后端的证据

本轮直接检查采样程序加载的 `_prev_archive_1.so`，不只依赖独立 `-gen_c` 后端：

- 原生提交块 `[0xd2a0,0xd389)` 先写2个单字节状态及5对32位四态平面，共12次目标存储；之后6次直接调用加1次尾跳进入7个生成后继。在这些目标写入与后继之间没有通用运行库调用。
- 原生传播块 `[0x9b80,0xa094)` 包含定宽切片、比较、变化检查及下游逻辑；其中有5个直接生成调用点，仅1个 `sched0lq_de` 排队请求点。它没有在每个中间信号后返回一遍通用 watcher/过程分派路径。
- 同源可读 C 提供相应的提交组与传播关系，派生事实单独记录；两种后端的时间/机器码不等同。这里的调用点数也不是实际调用次数或去重入队次数。

原生库SHA256为 `3b1eb28fb016c8a8d53b86194f613636c092e9c9eb86f2e397f34fda2126b90d`。检查使用具体地址仅用于核对这个冻结生成物；这些地址和设计名不进入 DSIM 优化实现。VCS 自身仍有显著运行库调度和通知采样，不能把它描述成完全静态执行。

## 泛化实现方向

1. **静态订阅与专用传播出口。** 对编译期已知、无动态事件表达式/过程控制/force等边界的静态连接，生成固定订阅或通知代码，减少容器遍历、目标查找及不必要的代数检查。保留 armed/queued、FIFO、事件观察以及预算语义；不能把所有后继无条件立即执行。
2. **组合依赖区域及过程基本块编译。** 从带类型的IR证明纯组合、单驱动、无环子图和合法执行区间，生成连续求值，减少逐信号物化和重复PC分派。过程内纯控制流与跨过程传播分别证明；观察点、延时、SCC、层次读取及跨过程交错必须形成边界。
3. **让固定 NBA 提交接入上述出口。** 静态目标与提交顺序合法时使用固定槽/成组提交，同时减少后续通用通知；不重复采用M116中“合并记录后仍逐个通用set”的失败路线。

以上规则都须在CPU之外的CRC、乘除、AXI4和独立合成结构上验证，并覆盖X/Z、窄化、组合链中间观察、阻塞/NBA混用、#0/正延时、精确预算及检查点预测/回滚。过去仅改setter分支和PC跳转的失败实验仍有效，当前热点不是要求重新默认启用那些候选。

## 原始数据与复现

在103运行 `collect.py` → `symbolize.py` → `native.py`，另运行 `count.py`，最后运行 `inspect.py`。脚本依赖报告指定的冻结M105/VCS/M126输入目录。`cpu_sample.c`是自有诊断代码，编译为 `gcc -shared -fPIC -O2 cpu_sample.c -o cpu_sample.so`；采样器发现既有SIGPROF处理器/定时器或处理器被替换时失败，不覆盖应用已有采样设施。

VCS生成源码和反汇编仅保留103的私有诊断目录 `/tmp/dsim-m127-cpu-gap` 及原冻结目录。自有脚本、原始PC/映射、完整输出、诊断模型和派生事实单独归档，排除VCS程序/生成源码/反汇编。归档及镜像核对见 [raw.json](raw.json)、[mirrors.json](mirrors.json)，结构化交叉核对见 [audit.json](audit.json)。本地与103的稳定入口继续使用M126，本轮不需重新发布相同生产代码。
