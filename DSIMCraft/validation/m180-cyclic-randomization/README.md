M180 adds native cyclic class randomization and per-call property selection. Feature implementation is 20a1ee50; c48fb827 updates parser recovery/clone checks; final production source c92b70b5 fixes allocator-dependent randomization callback ordering. Release and activation receipts identify the exact compiler, inputs and results.

randc has a separate declaration flag, preserved through parameterized syntax clones. Per-object, per-field history belongs to the checkpoint-owned object heap. The native Z3 solver detects related constraint changes using connected assertions, restarts exhausted domains, and gives cyclic properties value preferences before ordinary rand properties. Failed randomization preserves property values, skips post_randomize and discards active permutations, matching the tested VCS behavior. Rollback restores history, modes, fields, callbacks and RNG state.

randomize(a, b) selects receiver properties for this call, including scalar non-rand properties. Names bind in the receiver class, access checks use the caller, persistent rand_mode settings are preserved, and randomize(null) checks current state. Stable field names prevent unrelated variable-list changes from restarting a cycle. Ordinary interface methods named randomize retain normal caller argument binding.

The constraint group has twelve models, 37 frontend rejection cases, one X/Z runtime diagnostic, 220 captures and two prediction rollback/commit replay checks. Sources cover independent cycles/objects, seed changes, constrained 16-bit selectors, exhaustion, constraint/rand modes, signed 32-bit and 96-bit values, inheritance/specialization, non-rand/local properties, inline constraints and null checkers. Serial, time-wheel and threads=2 requests are checked; requests alone do not prove that a shared heap runs in independent partitions. The separate IPC guard asserts two actual partitions. The new repeated-emission test also compiles via short and long executable aliases/output names and requires identical callback storage and C++.
