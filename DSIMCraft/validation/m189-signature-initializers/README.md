# M189：子程序签名与局部声明分离

修复原版 UVM 的 `uvm_report_handler` 和 `m_inst_typename_alias_t` 两处阻塞。原实现注册方法签名时连带分析局部声明及初始化调用，提前展开后面定义的类，也让 extern 方法看不到类中稍后的 typedef。现在先绑定签名，局部声明按原顺序进入已有语义延迟队列；非 ANSI 签名保留截至最后一个形参的声明前缀。调用处克隆仍立即绑定全部声明，初始化在实际激活执行。普通函数、任务和 adopted extern 方法共用处理，没有按 UVM 名称特判。

三个新增模型：包内 extern 方法及后置成员 typedef、类 static 方法/任务和 65/129 位模块克隆、普通 ANSI/非 ANSI 函数与延迟任务。三个负例保证未使用子程序的错误初始化仍被检查、局部变量不能引用稍后才声明的局部类型。parser 单测反复解析、克隆、校验成员类型同一性以及失败恢复。

公开 UVM 2020.3.1 源码保持不变，1888084 字节预处理与 166 个依赖沿用既有哈希。首错推进至 uvm_factory.svh:619 的对象句柄关联数组键 `uvm_object_wrapper`（诊断 `type name is not a value`）。该类键尚未支持，完整 UVM 仍未编译运行；本轮不作性能结论。初版 10564cc5 的 stage 不激活，最终验收只采用后续结构修复候选，见 JSON 收据。
