报告中的 synthesis 注释和“144 位 RAM 特例”未作为根因照单修改：实际假循环来自不可达父模块的入度。原始 1024x144 模型基线 emit-only 可完成；32768x128 原表示生成约 379MB C++，揭示逐元素展开的规模问题。`{N{1{1'bx}}}` 和模块级 automatic 数据在本轮 VCS 探针中也被拒绝，不将非法形式作为兼容要求。

新增存储表示只自动扩展原先超上限的适用数组；较小数组须显式 `--compact-memories` 选择阈值 1024。默认既有整数组/波形能力保留，受限模式不能静默改变接口。`-y` 库搜索仍未支持。

首次全设计 ASan 发现 generate 临时壳释放后仍被子节点父指针引用；修正后又发现 `vtGENVAR` 和 `veEXP_MEMBER` 数值相同，队列辅助类型查询缺少 `tok_type` 检查。最终修正及直接 genvar 查询回归已通过完整前端消毒检查。原始失败日志保留在外置证据，不纳入成功计数。

`vcs.py`、`compare.py` 核对精确源 SHA 和完整 TRACE；`sanitize-models.py` 检查实际生成代码。`c910-vcs.py` 重编原设计；`run-little-endian.py` 仅复制并逐字反转镜像的四个字节；`native.py` 记录有预算的原生编译和运行。这个手写程序只证明最小 RV64 指令与 TB 成功通道，不代表 hello_world、CoreMark、ISA 或完整 VCS 功能覆盖。
