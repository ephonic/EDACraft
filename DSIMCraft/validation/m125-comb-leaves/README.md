# M125：纯连续赋值的直线执行体

在 M121/M122 批次以外，识别可完整执行的独立连续赋值，将正常激活的 wait/store/return 三条 PC 指令编译成直线代码。唯一整网驱动、静态 change 等待、纯标量表达式及现有批次边界的证明保持不变。原始 CPU/CRC/muldiv/AXI4 分别识别 27/9/11/31 个过程。

预算足够且 PC=0 时一次保留三条逻辑指令的预算；其余情况运行原 PC 解释器。GCC 将回退体放入只在本次调用存在的 `noinline,cold` 内层闭包，引用原过程拥有的 PC 状态，避免解释器代码挤占正常执行体的内联预算；Clang 使用已实测的原回退布局。源信号重武装、每个目标发布、订阅通知、FIFO 和 NBA 边界使用原实现。这个改动没有融合通用组合 DAG，也没有减少物理 Ready 出入；它只减少独立过程内部的 PC 解释。

`comb_leaves` IR 给出候选过程，`DSIM_REFERENCE_COMB_LEAVES=1` 恢复原执行体。诊断编译的 `comb_leaf_runs` 仅统计完整直线执行次数，不用于正式计时。

## 功能验证

macOS 和 Linux 的八个模型各通过 80 份 ordered/settled 波形、2104 组预算状态、16 次预测接受/拒绝对照。覆盖四态、64 位、窄化、高位变化、边沿、#0、NBA、连续链、已有批次及 force/宽值/延迟回退。Mac 两个生成模型通过 ASan/UBSan；103 缺少 `/usr/lib64/libasan.so.6.0.0`，Linux 的额外 sanitizer 程序未能链接或运行，明确记录为 UNAVAILABLE，不能计作通过。结果见本目录结构化 JSON；完整原始运行数据另外归档。

每端另外比较 576 组预算中断后的有界重复恢复结果。其中 469 组正常返回；107 组参考解释器也报错，候选的退出码、stdout、stderr 均与参考一致。参考路径在预算异常时可能丢弃已弹出的过程，因此这 107 组不能称作成功恢复；本轮没有修复这个既有问题。正常完整仿真必须通过所有输出检查。

## 性能采用边界

最初直接复制热执行体和原 PC 回退体，完整负载暴露出编译器差异。GCC 的 CPU 前缀 Ir 从 317447456 增至 342840168（+8.0%），更多 `get()` 调用退出内联；其生成源和 vector 归属的独占指令合计从 3781944 增至 20746008，解释了约三分之二的新增指令。冷回退体将该归属恢复到 3743928。这里不能只用代码布局或测量噪声解释退化。冷回退体初筛恢复收益后，冻结最终实现重新测量。

最终 Linux GCC 11.5，`-O2 -pthread`，固定 CPU0，一次预热加三轮换序；所有变体先编译完成，仿真期间没有本任务的编译/诊断任务。基线是经过 SHA 核验的冻结 M123 原生程序，四个完整原始负载全部输出一致。同批 VCS 默认原生后端：

| 完整负载 | M123 CPU 秒 | M125 CPU 秒 | 用时下降 | VCS CPU 秒 | M125/VCS |
|---|---:|---:|---:|---:|---:|
| CPU | 10.61 | 9.57 | 9.80% | 5.72 | 1.67 |
| CRC | 4.23 | 3.90 | 7.80% | 4.16 | 0.94 |
| muldiv | 8.49 | 8.40 | 1.06% | 6.93 | 1.21 |
| AXI4 | 0.22 | 0.21 | 短样本，不作收益结论 | 0.58 | 短样本 |

CPU 的比值从 1.85 降为 1.67，差距仍大。乘除法样本存在重叠，改善较小。共享服务器有其他负载，VCS 的墙钟还包含明显启动等待（CPU 用时 5.72s 对应墙钟 8.52s）；表格只比较进程 CPU 中位数，不把它称作端到端墙钟加速。所有样本及墙钟另见 `linux-full.json`。

macOS Clang 独立三轮 CPU 中位数：CPU 6.102687→6.004980s（1.60%，改善较小），CRC 2.553424→2.479538s（2.89%），muldiv 5.290268→5.116115s（3.29%），AXI4 0.123612→0.122588s（短样本）。见 `mac-full.json`。GCC 冷回退修正前的两端样本保留在 `pre-cold-*.json`；该版 Linux 的退化没有进入稳定入口。八个 Clang 模型最终与先前完整回归模型的预处理内容在归一化空白后相同，见 `clang-proof.json`。

## 工作量核对

非统计编译的固定前缀 Callgrind Ir：CPU 317447456→305712346（3.70%），CRC 79157994→74825994（5.47%），muldiv 77658397→75950627（2.20%）。Ir 是执行的指令数，不是硬件周期或采样 CPU 百分比。三个前缀的逻辑步分别保持 5767258/1754473/1242666，全信号哈希逐项等于此前冻结的历史输出。

另行统计编译中，完整直线体分别执行 385605/64688/38836 次；Ready 出入分别保持 957631/144694/181892，各自候选和参考完全相等。由此确认这轮收益没有来自少仿真事件或改变预算计数。完整数据见 `profile.json`。

## 复现

- `tests/comb_leaves/regression.py`：使用构建目录 CMakeCache 获取 zstd，运行生成模型及参考模型。
- `measure-mac.py`、`measure.py`：冻结 M123 原生程序作基线，四个未改动的完整负载，预热后换序三轮；所有模型先完成编译再计时。
- `profile.py`：200000000 tick 前缀，比较原始历史逻辑步骤及全信号哈希，分别采集非统计 Ir 与独立队列/执行计数。
- `check-vcs.py`：同源四态边沿及组合链探针。边沿计数从零时刻稳定后开始，避免把独立观察进程的启动竞争当作功能差异。
- `publish-linux.py`、`verify-installed.py`：冻结源码包构建、测试后切换，再从安装入口重生成并运行四个完整负载。

第三方 VCS 的生成源、反汇编及二进制留在 103 的临时诊断目录；本目录不收录这些文件。
