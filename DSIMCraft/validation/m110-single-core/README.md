# M110 single-core execution efficiency

The implemented change is [automatic scalar function storage](../../docs/function-locals.md). It reduces generic signal accesses within private automatic calls while retaining four-state values, original instruction budgets and exact exception state. Functions needing observers or unsupported storage retain their original path. This is not a new language feature, broad RTL process fusion or a multicore result.

`measurement.json` contains all 48 full original workload runs: frozen M109, M110 and the unchanged VCS W-2024.09_Full64 programs; all pinned to CPU 0, GCC 11.5 O2 pthread, one warmup plus three rotated rounds. `audit.json` independently recomputes every raw GNU time sample, median, ratio and complete output. CRC improves from 6.30 to 5.24 CPU seconds (16.8%), compared with VCS 3.89 seconds. CPU and muldiv have no demonstrated runtime gain; CPU's old/new executable hashes are identical. CPU/CRC/muldiv require 2.93/1.35/1.70 times VCS CPU time. Short AXI4 timings include startup and are not used as a throughput claim. Shared-host load and frequency remain uncontrolled.

`profile.py` compares the exact same active prefix, executed-step count and full state hash. CRC instruction count falls 11.4%, muldiv 0.75%, CPU unchanged. `screen.py` and `inline-screen.py` record provisional experiments; set/notification splitting and forced inlining were withdrawn. Provisional timings are not mixed with final data.

The new differential regression has 12 complete VCD captures, 187 budget/state comparisons and two prediction outcomes. `development.json`, `affected.log`, `kernels.log` and `sanitizers.json` record development checks. Release receipts and installed-entry checks are added after immutable source freeze. Raw timing/generated-source and profiling artifacts are kept separately from Git and identified by digest in the final receipts.
