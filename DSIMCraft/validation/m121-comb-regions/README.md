# M121：合并组合赋值的物理调度

实现冻结 `ad75686da3a0351539e163e1635bb6fafa424aea`，基线 M120。本轮默认采用相邻、相同敏感列表的组合批次，实际减少 watcher 和 Ready FIFO 条目。没有修改 RTL、TB、输入、仿真工作量或逻辑事件预算。

## 确实减少了哪些工作

CPU 设计中 32 个连续赋值合为 8 个批次。成员和等待点注册顺序都必须相邻，具有相同静态输入集合；目标是唯一驱动、无初始化/位别名的整网，不能写共同输入。表达式仅允许无副作用、无内部预算指令的标量运算。

原来一个输入变化依次扫描多个成员 watcher，并为各成员写入 Ready FIFO、调用带 PC 的过程闭包。现在只保留一个 watcher、入队一个令牌，执行生成的顺序赋值体。每个逻辑赋值仍计算、每个输出仍按原序发布；该输出引起的唤醒追加到原 FIFO 尾部。没有跨过其他已排队过程，也没有在 NBA 批次中途运行组合体。

固定 200000000 tick 前缀、相同时间/逻辑步数/全信号状态哈希下的实际计数：

| CPU 前缀指标 | M120 参考 | M121 |
|---|---:|---:|
| Ready 入队条目 | 1321651 | 1017631 |
| Ready 出队条目 | 1321651 | 1017631 |
| watcher 条目 | 349 | 325 |
| 默认版合批覆盖的逻辑成员执行 | — | 416025 |
| 对应物理批次执行 | 原逐成员调度 | 112005 |

每次出入减少 304020 个条目，即 **23.0%**。计数满足精确守恒：416025−112005=304020。不是删除逻辑赋值，也不把输入通知数、过程数和 NBA 记录跨单位相除。统计版本单独编译，不用于耗时结论，见 [scheduling-stats.json](scheduling-stats.json)、`stats.py`。

非统计版本 Callgrind 的 CPU 前缀指令从 357422352 降到 319021981（10.74%）；CRC、muldiv 指令完全相同。CPU 前缀仍为 5767258 逻辑步，全信号哈希 1604582946171822610。见 [profile.json](profile.json)。前缀的指令/队列下降比例不等于完整负载耗时下降比例。

## 预算、观察和快照边界

批次保留每成员一次调度加三条指令的逻辑预算；有足够预算才执行直线体。接近上限时，在原 FIFO 位置展开为原过程，然后继续原 PC 执行。展开后该批次持续回退，因为预算异常可能把原闭包 PC 留在赋值中间，后续不能假定从头开始。

Sim 拥有重新武装掩码、待执行掩码 FIFO 及回退位；检查点深拷贝这些状态，允许部分恢复后有新输入、反复恢复及预测接受/拒绝。输出发布和 ordered 波形逐项保留。复杂等待、进程控制、force、宽值/字符串、门级时序、并发属性及实际多分区保持原路径。

`--emit-ir` 的 `comb_regions` 列出成员与输入。`DSIM_REFERENCE_COMB_REGIONS=1` 恢复参考；禁用等待重武装缓存也会禁用合批。批次最多 16 个成员，直线体不会无限展开。通用 DAG 区域融合、跨区域事件消减和固定 NBA 分组仍未完成。

## 功能验证与构建代价

- 六组 RTL：普通/多输入/多级批次、NBA 与 delta 连锁、诊断报告、非相邻成员、函数副作用/反馈/多驱动回退、force 和连续延迟。默认/参考/时间轮/并行：52 份完整 ordered/settled 波形（含跨信号事件顺序），1182 组精确预算及全信号状态，4 次预测接受/拒绝。
- 新内核对照 520 个完整状态，包含预算中断后的 PC、逐过程 queued/waiting/代次/等待点、部分重新武装后新输入、待执行检查点重复恢复和预测接受/拒绝。四项既有 runtime/驱动/编译过程/固定等待内核及两个新内核通过。见 [regression.json](regression.json)、[kernels.json](kernels.json)。
- 两个内核变体及真实 NBA 连锁生成程序 ASan+UBSan 通过，见 [sanitizers.json](sanitizers.json)。
- 两端发布检查 comb_regions、gate_source，另有 RTL/格式 parser 和原生 DB；Linux 另七项内核。安装入口重新生成并完整运行四个原始负载，要求 CPP 和输出与正式实测逐字节相同。

同源 VCS 对照使用未改写的 cohorts/boundaries/diagnostics：17 行 TRACE 的各观察进程内部次序及 181 个静态数值位的完整 settled 时间线一致，见 [vcs.json](vcs.json)。最初把所有独立 Active 观察进程的打印强制排成同一个全局次序，cohorts 因 x/u 观察进程交错不同而失败；数值和各进程序列相同，故修正跨仿真器比较口径，保留 [初始差异](vcs-initial-comparison.json) 和原始日志。dsim 默认/参考之间的严格全局打印和 ordered 波形比较未放宽，RTL 源也未修改。诊断文本采用各仿真器格式，VCS 对照只核对 TRACE 和数值时间线。

CPU CPP 为 346499 字节（M120 320731），`.text` 为 137612 字节（参考 126293）。保留原闭包供精确预算回退，因此代码体积增长约 9%。另一次单对构建记录编译 CPU 时间 4.50→5.03 秒、墙钟 4.53→5.48 秒；这只是构建代价样本，不是稳定的编译吞吐测量。重新构建的 CPU 默认/参考 text/rodata/data 均与实测二进制逐字节相同。见 [build-cost.json](build-cost.json)。
