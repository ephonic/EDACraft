## 已确认的调度策略

**组合链可以编译成连续计算。** 探针为 `x=a+b; y=x^常数; z=y+q`。可读 C 为 a/b 两个变化入口各生成一段包含两次加法和一次异或的计算，三段算术间没有调度调用；最终值变化时才请求边界作业。默认原生库也存在两段同样结构的机器码：从入口到返回，只有链尾一次 sched0lq_de 请求，没有其他 call。它不是把三个 assign 分别翻译成原生算术之后，仍逐级返回通用调度器。

这不等于只在周期末计算一次。阻塞赋值源更新后仍可能先后触发不同入口，内部值仍有存储；探针也没有证明所有中间事件都被删除。确认的是融合了该链的一段求值和传播路径。

**固定 NBA 槽与成组提交。** 探针的 q/n 两次非阻塞赋值共享一个 NBA 请求位置及一个固定对象；RHS 写固定实例偏移，提交回调先写两个目标的四个位平面，再直接调用生成后继。完整 CPU 的同类回调仍是先提交多个目标，再调用七个后继。请求次数、去重后的入队次数和回调执行次数是不同单位，不能用请求比推算加速比。

**直接后继包含计算，也会保留排队边界。** 完整 CPU 的七个后继中，1c 执行值变化和简单逻辑检查后调用 sched0lq_de；1d 在变化检查后直接做指令译码、切片和布尔计算，部分路径才请求该边界。1e/1f/22 又直接调用其他生成传播函数。这里已超过“回调只负责通知”的情形，但也不能把所有直接函数调用解释为任意过程立即执行。

**触发连接与状态是专用的。** 小探针的时钟变化处理使用四态边沿表、固定 armed 字节和确定的过程回调；边界请求前检查固定 queued 位。它仍有 armed/queued 判断和运行时调度，却不需要每次遍历通用 vector watcher 再解释目标及边沿类型。

**观察点和延时影响融合范围。** 加入 `always @(x)` 后，可读 C 的链计算入口由两个变成一个，该入口的边界请求位置从一个变成两个；加入 `assign #1` 后，包含异或的函数只剩下游一次加法。具体表明代码生成会随边界改变，不能无条件融合所有零延时语句。OBS 在 Active 中读其他变化值存在竞争，其输出仅用于检查本机两后端行为，不是规范唯一排序。延时探针在边沿后 #2 才显示，避开 #1 交付与显示同刻的竞争。

**延时事件有时间桶和短延时路径。** 实际 rmapats.c 使用目标时间低位掩码选桶，已有桶尾插，delay=1 可走 FutQ1 尾插，低时间字溢出进入 sched_millenium。这里只证明生成代码存在这些路径，没有证明它们是当前负载速度优势的主要来源。

单独减少边沿解码的两个候选没有稳定整体收益，已撤回，见 [失败实验](../m124-change-stores/README.md)。这支持转向减少传播次数和执行粒度，而不是继续只精简 setter 的某条分支。它仍不足以给 VCS 的优势分解出准确因果百分比。

## 下一步修改顺序

1. **先做组合依赖区域与边界识别。** 在 elaboration/lowering 后保留赋值目标及表达式语义，识别单驱动、纯组合、无环区域；将事件观察、层次读取、延时、SCC、force、多驱动、断言及跨过程交错列为边界。先统计 CPU 热链的覆盖与回退原因，避免建一个不覆盖热点的通用框架。
2. **为合法区域生成直线求值和专用出口。** 局部位平面临时值传递，仅在需要可见值或事件的边界发布；区域内不逐信号调用通用 set，不逐级进入 watcher/PC 闭包。多个入口、共享子表达式及出口去重按已证明的事件顺序处理。普通模型保留原路径，提供独立关闭开关。
3. **把固定 NBA 槽接到上述区域。** 先保证一个提交作业内的目标更新完成，再处理其合法传播边界；跨 NBA 作业和 Active 的顺序不能从本探针泛化。M116 已否决单独分组再调用通用 set 的路线，重新尝试必须同时减少发布及传播工作。
4. **用计数和原始完整负载验收。** 看 set/通知/物理队列/过程执行实际消除量，再测同机同核预热换序的 CPU 和墙钟。保留四态、NBA 连锁、观察点、延时、精确预算继续运行及快照回滚验证。单线程先完成；本轮未发现应优先用 MKL、多线程或预测回滚替代该工作的证据。

本轮为检查与方向收敛，没有采用新的 runtime 优化；Mac 与 103 稳定入口继续使用已验收 M123。不能把本报告表述为结构性融合已经完成。

## 复现

在已有冻结 M105/M115/M123 私有目录的 103 主机，先 source `/apps/EDAs/syn.bash`，再运行：

```
python3 collect.py --root /tmp/dsim-m124-vcs-inspect
python3 inspect.py /tmp/dsim-m124-vcs-inspect
```

源码及脚本可放在任意目录；collect.py 默认读取同目录 probe.sv。inspect.py 的部分函数名、固定负载和 C 语法检查针对当前 VCS W-2024.09，升级后应重新确认，不应静默忽略断言。
