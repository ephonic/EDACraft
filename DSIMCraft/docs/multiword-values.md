# 多字四态值与原始宽接口

编译器根据展开后的信号、常量、赋值目标和拼接表达式选择值后端。存在超过64位的值时，生成程序定义 `DSIM_WIDE_VALUES` 并嵌入 `wide_value.hpp`；不需要用户切换parser或拆分顶层端口。只在中间拼接超过64位、最终赋给窄信号的情形也会启用。普通窄程序的V仍为24字节，未增加尾部所有权字段。

宽后端保留低64位a/b平面，额外字使用不可变共享尾部。读、事件复制、NBA队列和检查点可以共享尾部；运算与部分更新产生新值，避免原地修改污染历史快照。零高位可省略尾部存储。每个word使用64位a/b表示0/1/X/Z，基础算术按word执行，不展开为逻辑门。

已实现无符号加/减/乘/除/模、逻辑移位、位运算、逻辑与/或、关系与四态相等比较、归约、未知条件分支合并、case/casez/casex匹配、拼接、常量选择、部分更新、多驱动网解析及二/八/十/十六进制显示。乘法使用32位乘积累加，除法为多字恢复除法；大除法性能仍有优化空间。RTL词法器补齐未定宽x/z literal，仍与门级结构parser分离。

沿用现有连接、驱动和调度机制，因此宽端口的input/output/inout、常量部分选择和重叠拼接NBA可以使用统一值类型。DWF仍使用原有格式：宽值走动态长度plane/XOR编码，常量0/1/X/Z保留单字节标签，块checkpoint保存完整宽值；原40字节临时缓冲只用于窄值。VCD及独立Python DWF reader不需要新格式版本。

实现上限与现有DWF reader一致，为1,048,576位；当前主要功能验证集中在64位边界以及65/127/128/129/256/257/512/1024位；上限是资源保护边界，未作百万位复杂算术的性能保证。限制仍包括RTL升序packed range、unpacked array、动态选择及signed运算；这批没有实现这些语言功能。repeat使用64位运行时计数器，已知且超出计数器的宽值明确失败，不截断高位。

验证通过独立Python大整数/逐位四态参考、完整编译程序和VCS差分分别进行。数值检查不替代端口/事件语义检查；手工保守通道的宽值运输也不等同自动门级分区。真实网表通过与后续SDF阻塞以validation/m4-wide-values中的实际结果为准，本批不据小例时间声称一般性能或压缩收益。

本批采用验证：两平台各45项累计通过（完整44项及修正旧宽度拒绝预期后的1项定向重跑），同一编译核心未因该测试修正发生变化。23,496项独立Python整数/逐位四态对照；五组新VCS流程的TRACE和选定位通过，其中256位SDF例注解0错误/0警告。三组实际生成boundary/replay程序及独立数值/并行程序经ASan/UBSan验证，未将整编译器称作sanitized。

真实原始300,909单元网表直接使用256/257位接口，128笔输出逐笔匹配新编译VCS。已有激励下简单a*b%p公式与110笔结果不同，而native和VCS完全一致；保留差异，不作算法数学正确性或设计错误结论，不为追求公式相符修改网表/刺激。全量SDF诊断独立记录；零延迟128笔一致不等于完整时序通过。本批无新的性能比、通用压缩率或自动并行收益声明。
