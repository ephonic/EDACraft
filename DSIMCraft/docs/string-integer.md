# 字符串整数解析、格式化及 putc

M100 新增以下方法，用于测试平台解析数据和构造文本。不是完整字符串或 VCS 兼容声明。

| 方法 | 行为 |
| --- | --- |
| `atoi()/atohex()/atooct()/atobin()` | 返回 signed 32 位整数，分别使用十、十六、八、二进制；超出范围按 32 位回绕 |
| `itoa(i)` | 将 signed int 写成十进制字符串，正确处理最小负数 |
| `hextoa(i)/octtoa(i)/bintoa(i)` | 将低 32 位写成无符号进制文本，不保留多余的前导零；十六进制使用小写 |
| `putc(i,c)` | 修改指定字符；索引先转 int，字符先取低 8 位，零字符、X/Z 和越界不修改字符串 |

解析跳过下划线，允许开头的正负号；遇到空白或非法数字停止，无法解析返回零。按本轮 VCS 实测，还支持对应的小写 `0x/0o/0b` 前缀，大小写不混用。不是 C `strtol` 的自动进制/空白处理。格式化输入先按 int 转换；X/Z 输入的十进制、十六进制、八进制返回 `?`，二进制保留 X/Z 字符。

修改方法使用已有的整变量写入路径，保留 automatic 激活、ref 的实时可见性、const ref 写保护、依赖分析和预测回滚。实参从左到右各求值一次，`putc` 在实参求值后读取字符串，避免实参函数通过 ref 修改同一个字符串时使用旧副本。修改方法没有返回值；非 void 方法可作为语句或通过 `void'(...)` 丢弃结果。

实数、字符串数组/端口、完整格式扫描和完整隐式转换仍未实现。本轮未修改整数循环热路径，性能数据仍以 M98 的测量版本和负载为准，没有新测速结论。

## 与本轮 VCS 的已知差异

103 的 W-2024.09_Full64 实测中，`putc` 的宽实参并不总是按 int/byte 截断：64 位索引 `64'h100000001` 未按 1 生效，字符 `16'h5141` 使用了 `Q`。dsim 保留低 32/8 位规则，与现有字符下标赋值一致。[Accellera 的 putc 勘误说明](https://www.accellera.org/images/eda/sv-ec/att-2285/issue_275.pdf)明确列出了 int/byte 原型、低 8 位和下标赋值等价关系。

同一 VCS 中，`itoa/hextoa` 修改字符串没有唤醒 `always @(text)`；dsim 的修改方法与阻塞赋值一样通知实际值变化。保留独立同源 `boundaries.sv`，分别检查两工具的预期并记录波形差异，不把它算作对齐通过。其余五个模型检查完整输出与所有物理位，详见 [M100 验收](../validation/m100-string-integer/README.md)。
