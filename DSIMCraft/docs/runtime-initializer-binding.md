# 运行期初始化与默认实参的绑定

M192 修复在包、模块或类的声明尚未完成时，过早展开运行期调用的问题。前向类型已声明，但其类定义依赖更后面的另一个前向类型时，原来整型初始化或默认实参中的调用可能报 `unknown integral type`。现在存储与子程序签名先注册，包含函数或成员访问的外围初始化表达式，以及声明中的默认实参，进入已有的语义延迟队列。参数常量表达式、普通常量初始化及调用处的 activation 克隆仍沿原有路径处理。

默认实参保留前序形参覆盖作用域；默认值仍在实际调用时求值，显式实参覆盖默认值。函数、任务、静态方法、extern 和 modport 继续共用参数绑定。即使子程序没有被调用，错误的默认表达式仍必须诊断，不能通过跳过检查解决问题。RTL 和门级 parser 保持独立。

新增用例覆盖包内整型初始化、模块内 integer/int/string/65 与 129 位初始化，以及函数、类静态方法、延时任务的默认调用。通过修改包变量后再次调用，检查默认值读取调用时状态；另加入未使用子程序的错误默认调用诊断和前向类型重复解析检查。验收收据见 [M192](../validation/m192-init-binding/README.md)。

未修改的公开 Accellera UVM 2020.3.1 已越过 `uvm_report_handler` 的这条提前展开路径，下一处实际阻塞是关联数组索引类型检查。完整 UVM 仍不能原生编译执行；这批不改变调度器或声称速度提升。
