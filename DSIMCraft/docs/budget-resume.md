# 执行预算耗尽后的过程恢复

M135 为生成过程的 PC 指令边界加入可恢复的预算异常。中断时保留当前 PC，把该过程放回其原执行队列的最前面；继续仿真时直接执行待完成指令，避免重复 wake 或 dispatch 计费。普通 Active 过程与并发断言 Reactive 动作使用各自队列；批次不能吞掉带有恢复标记的事件。保存的 checkpoint 同时保留恢复事件、过程 PC 和原有模型状态。

`InstructionBudgetExhausted` 表示本次失败发生在分派/生成 PC 指令的副作用之前。捕获后提高 `Sim::limit` 可继续执行，也可保存/恢复该中断状态；例如设为 `s.executed_steps() + more_steps`，为下一次实际执行留下正的预算。`executed_steps()` 包含失败的计步尝试，因此最终步数等于完整运行的正常步数加上中断次数；不会额外收取过程重新分派步骤。

这不是任意 C++ 调用栈的恢复。内嵌函数的临时 PC、用户自定义 callback 及内部 `step()` 仍可能在一条外层指令的部分副作用之后中断；它们不抛出上述可恢复类型，不能盲目重执行。此类失败需恢复到中断前的有效 checkpoint。M135 没有完成函数调用栈续跑、任意门级 handler 或多分区执行器的完整预算恢复，保留为后续缺口；也不声称所有历史 reference 错误已消失。

验证使用旧 RTL 边沿/四态/组合过程、分支控制、SVA Reactive 动作及 automatic fork 共享帧。每个预算中断恢复后的全部输出、完整 ordered VCD 和逻辑步骤，对照同源不间断运行；额外检查多次小预算续跑和 checkpoint 复制/恢复。函数含副作用的负例确保函数内部异常不会被误作安全重入。波形 checkpoint 仍要求 `predict_until` 事务，普通中断 checkpoint 用不启用波形的运行单独验证。

本批是功能修复，不开展性能测量。验收记录见 [M135](../validation/m135-budget-resume/README.md)。

M158：默认仿真不再施加隐含的一千万事件/指令上限。`Sim::limit` 的默认值为 uint64 最大值，串行、带波形及非波形并行入口一致；运行参数 `--max-events N` 和 API 显式设置 limit 继续限制实际执行，预算中断、继续与 checkpoint 语义不变。此项针对已复现的合法长函数/内存测试被默认预算提前终止，不改变用户显式请求的预算。
