# 未打包类型别名与数组值调用

M162 保留 `typedef int Q[$]`、`typedef T D[]`、固定多维数组及链式别名的维度、容器种类、队列上界和元素类型身份。模块克隆、包导入和参数化类特化均重新绑定形状，不共享另一实例的范围节点。RTL 和门级 parser 继续分开。

函数可以返回队列、动态数组及固定多维数组。返回值在 automatic 调用帧恢复前按值保存，数组元素按声明顺序传递；类元素复制句柄并保留对象身份。支持数组返回值赋值、作为 input 实参、嵌套函数返回以及临时结果的 `.size()`。队列和动态数组支持普通 `{a, b, scalar}` 数组拼接初始化与赋值。固定数组仍使用已有 assignment pattern 路径。

类型别名及直接声明的队列形参支持 input、output、inout、ref、const ref；引用检查元素类型、容器种类和队列上界。队列复制经过目标上界约束。虚方法覆盖检查数组形状和元素身份，参数化类返回类型也可用于 pure virtual/function 原型。

新增回归覆盖四态与129位元素、两态转换、enum、类句柄/虚拟派发、参数化克隆、延时任务引用、初始化生命周期、函数返回、预测回滚/提交和实际两个并行分区。原始 REPORT-GAP2 `r02_adt_deep.sv` 字节不改纳入测试。执行结果同时检查 VCD、同步 DWF、独立线程异步 DWF，以及用户指定信号和时间范围。

本批仍有边界：不支持关联数组形参/返回值、string 数组签名、嵌套运行时容器、数组返回递归、数组临时结果的一般索引/归约，以及固定数组接收函数结果时的 NBA/赋值内延时。`return {}` 的空队列表达式仍需补充；负例中的非空返回用于独立检查覆盖签名和递归限制。已有支持不等于任意 SystemVerilog 数组表达式都可用。

未修改 Accellera UVM 2020.3.1 的 native 首错推进至 `uvm_coreservice.svh:165` 的 `local` 声明，**完整 UVM 仍不能原生编译运行**。受约束随机、mailbox/semaphore、clocking/虚拟接口、功能覆盖及 DPI 等 REPORT-GAP2 目标继续保留。103 当前无响应，本批尚无新 VCS/Intel 对照结果，也不作性能结论。具体验收见 [M162](../validation/m162-array-aliases/README.md)。
