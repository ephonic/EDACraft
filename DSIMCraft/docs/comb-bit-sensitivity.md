# 组合块的静态位区间敏感性

`always_comb` 和 `always_latch` 支持对同一 packed 变量的不同静态位进行读写。例如：

```systemverilog
logic [3:0] q;
always_comb q[3:2] = q[1:0];
initial begin
  q[1:0] = 0;
  #1 q[1:0] = 1;
end
```

`q[1:0]` 的变化会唤醒组合块；本块写入的 `q[3:2]` 不会使它自触发。若只读取 `q[0]`，其他未读取位的变化也不会额外唤醒该块。其他过程可以写互不重叠的静态位；重叠写仍报错。

编译期保留词法读表达式及函数体依赖，识别静态位选择、片选和 packed 字段前缀，将静态写区间从读取区间中扣除。剩余区间使用已有的 expression wait 回调检查四态变化，不重新执行用户函数来评估敏感性。整变量赋值继续走原有路径。多个部分赋值覆盖整个变量时，也可以完全排除该变量的自触发。

适用范围包括固定数组元素、packed 结构和多维 packed 变量、宽向量、嵌套函数读取与静态写副作用，以及动态读取选择的静态基对象。任务体的隐藏读取不加入 `always_comb` 敏感性，保持现有任务语义。分区仍使用完整变量依赖，避免将共享向量的不同位错误拆成独立分区。运行时使用现有等待状态及 checkpoint 恢复机制。

动态写目标缺少静态整变量赋值时，仍可能需要更完整的动态前缀分析；当前继续明确拒绝这类读写反馈。可写 `ref` 参数的实际位范围也没有在本轮细化。普通 `always @*` 的敏感性规则不变。

永久回归位于 `tests/comb_sensitivity`：三后端、回滚、真正双分区及写冲突拒绝。`reported` 原样保存用户 `overlap48_hand` 的 DUT/TB，覆盖196次48位双输出观察；其此前编译失败已由M88整字赋值支持修复。本轮进一步覆盖无需整字赋值的静态反馈。
