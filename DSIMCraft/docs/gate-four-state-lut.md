# 小型组合输出的四态查找表

编译器对读取 2–4 个不同输入 pin 的纯组合输出生成最多 256 项查找表。程序启动时使用原生 V 表达式枚举全部 0/1/X/Z 组合，随后每次输出求值读取当前 pin、拼接位平面索引并取表值。含存储状态的表达式保留原路径。RTL 与门级 parser 仍分开，runtime、驱动身份、敏感列表和调度阶段不变。

每个输出单独读取输入，不能缓存整个模型的一份输入：前一个输出驱动可能通过别名改变后一个输出的输入。三态与未知值也保留原生表达式语义，不能将 `a ^ a` 对 X/Z 无条件折为零。表是只读的，不增加检查点/回滚或并行 worker 的可变共享状态。

真实设计 89 模型的 98 个输出应用此变换。179,648 组普通/紧凑网、全部四态及输入输出别名/多输出别名的有序通知对照通过；普通与实际 ASan/UBSan 均运行。24 个完整生成模型在 macOS/Linux 逐字一致，18 条完整有序波形与已验收版本及两平台一致。8 个实际生成的检查点/回滚程序另经 ASan/UBSan，普通 RTL 计数器生成代码逐字不变。

独立七次真实设计交替配对，CPU 9.87→9.47s（中位数之比减少 4.05%），**配对收益中位数 3.86%，六对改善**。100k ff 反馈五对的配对中位数慢 1.23%，在预设的 3% 回退限制内；不能称所有负载均提速。

实际编译器重新生成/编译后，仅多一处重复标准头引用；完整预处理结果与筛选候选逐字一致，两个负载的 ELF SHA 也完全相同。新同轮单核三次 CPU 中位数：

| 负载 | 已采用原版 | 查找表 | VCS |
|---|---:|---:|---:|
| 原始 300,909 单元 /128 组完整 golden | 10.11s | 9.64s | 7.76s |
| 100k ff 非规则反馈 | 3.85s | 3.83s | 5.59s |

真实设计约为该轮 VCS CPU 的 **1.24 倍**；墙钟中位数分别为 10.15/9.68/10.73s，RSS 为 73,576/73,856/195,560 KiB。VCS 使用 SHA 固定的既有编译程序，本轮重新运行；所有运行核对完整 oracle。无 SDF、无波形、固定一个逻辑 CPU、共享主机未锁频，不推广为完整 VCS 性能对齐。原始离散值全部保留，包括独立复测中一次真实候选变慢，以及新反馈轮的 4.41s 候选；不删除异常点或混用不同轮 VCS 分母。

源、计时、输入 SHA、验证脚本及完整证据在 [本批记录](../validation/m5-gate-lut/README.md)。下一步按新热点分别评估表达式复杂度筛选、常量传播与 watch/队列成本；一般 SDF 回标、自动分区和波形扩展继续推进。
