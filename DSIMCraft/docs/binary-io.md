# 二进制文件输入（M107）

RTL 编译器支持 `$fread(destination, fd [, start [, count]])`，返回实际消耗的字节数。它与 `$fgetc/$ungetc/$fseek/$rewind/$feof` 共用文件映像、位置及推回状态，并接入预测提交/回滚、函数写集和并行 I/O 依赖。

支持范围：

- packed 整数变量、固定数组元素及 packed 切片，包括非字节整宽、超过 64 位的值和二态目标。
- 整体固定一维未打包数组；按数值下标递增读取，数组声明方向不改变文件字节顺序。
- `start` 是数组下标；省略时从最小下标开始。`count` 是元素数；省略时读至最大下标，过大的正数被截断，零不消耗输入。
- automatic 局部变量及已支持的标量/固定数组 `ref` 形参；地址副作用、函数写回、真实独立分区和预测回滚均有回归。

文件字节先进入目标的高字节，再进入低字节。非整字节宽度丢弃最高字节中超出目标宽度的位，例如 12 位目标读取 `12 34` 得到 `234`。

与 103 上 VCS W-2024.09_Full64 的同源实测一致：整体 packed 变量短读时低位补零，即使一个字节也没读到仍置零；选中的数组元素或 packed 切片只有读到至少一个字节才写回，零字节时不求值目标地址。整体数组只存储完整元素，末尾不足一个元素的字节仍计入返回数及文件位置。描述符/范围实参先求值，目标动态地址随后在实际写回时求值。

当前明确拒绝动态数组、多维数组/子数组、聚合成员或拼接目标、string 和 enum 目标，以及 packed 目标上的 start/count。内存声明仍受既有非负下标限制。数组起点越界、负 count、X/Z 描述符或范围会报错；无效范围的告警/恢复行为尚未与 VCS 对齐。尚无 `$ferror`、完整实数文件输入或交互输入支持。

验收见 [M107](../validation/m107-runtime-binary-io/README.md)。五个模型逐行核对 VCS 输出、输入字节和数值位时间线；VCS 的 `$dumpvars` 不输出未打包数组，其内容由 TRACE 核对。另有一项明确记录的 VCS VCD 差异：整体 packed 变量在零字节 EOF 读取后，VCS 的 TRACE 返回新零值，但 VCD 未记录该次变化。对照脚本严格断言这一具体差异；dsim 保留正确的新值和波形，不将它算作相同的时间线。三后端及接受/拒绝预测之间仍要求全部波形一致。
