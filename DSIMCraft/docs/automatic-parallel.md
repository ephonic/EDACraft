# 普通 RTL 自动并行编译

实验选项 `--threads 1..128` 已接入实际编译流程，默认关闭。RTL 与门级 parser 继续分离；在 RTL 层次展开和门级绑定完成后建立整个程序的依赖图，再生成独立内核。

```sh
./build/dsim --threads 4 --wave-support --emit-ir partition.json -o simv design.v
./simv --parallel-stats --waveform wave.dwf --wave-compression-jobs 4
```

实际划分只有一个分区时，包括 `--threads 1`，直接生成原串行内核代码，避免 ID 映射、线程池和窗口事务开销。生成代码仅增加 `--parallel-stats` 参数适配，统计为一个分区、零窗口和零消息；IR 中 `parallel.execution` 为 `serial-fallback`。两个及以上分区使用 `conservative-kernels`，实际 worker 数不超过有工作负载的分区数。省略选项继续使用原串行后端。

## 分区和执行

过程的读写、显式事件敏感信号、端口别名和双向位连接决定必须合并的域。打印、全局时间格式与结束任务所在的过程相互合并，保留这些副作用之间的顺序。按静态指令负载把独立域分配到内核，信号、过程、等待点和连续赋值通道使用安装后只读的全局到局部 ID 映射。

每个 gate scope 连同全部端口保持为一个域，支持当前 SDF、紧凑网、专用作业、路径表和波形入口。此版本不在 gate scope 内部切边，也不按 RTL `#delay` 自动切出正延迟通道。因此 `parallel.cut_edges` 为零；当前自动代码生成能并行执行互不相连的域，已有 API 的正延迟跨分区通道仍由调用方连接。

`ConservativeSim::run()` 和 `AutoConservativeSim::run()` 按下一个真实事件或未交付消息推进，支持自然静止结束，不要求人为提供有限仿真终点；稀疏时间跳过空白区间，最终时刻保持在最后活动点。多分区仍需在事件前沿同步。编译器仅在程序中存在 `$finish` 时启用全局结束快照；没有该任务时省去这项整状态复制，打印和波形仍在窗口完成后归并。IR 的 `parallel.global_finish_transactions` 表示是否生成该配置。尚无这两项消减的 CPU 加速比。

## 语义与限制

- Active、Inactive、NBA、四态、多驱动、宽值、连续赋值延迟和延时 NBA 在所属内核中继续使用原有事件语义。
- 共享打印、结束与时间格式不会跨内核竞争；各内核的打印和单文件波形在窗口提交后归并。独立域同刻的全局交错采用物理分区 ID 顺序，改变分区映射可能改变与 `$finish` 同刻竞争的可见前缀，不能宣称与任意串行/VCS 有序流等价。
- VCD、raw DWF、Zstd DWF 和异步压缩可用。`$dumpvars/$dumpfile/$dumpon/$dumpoff/$dumpall` 与 `--threads` 的组合当前明确拒绝；可使用 `--wave-support` 和运行时 `--waveform`。
- `--max-events` 是各内核的工作预算。所有时间保持整数 tick；并行运行拒绝 `UINT64_MAX` 时刻的活动。
- 含 `$finish` 的多分区仍使用整状态事务复制，负载估计、逐前沿同步和独立域粒度仍需优化。无全局结束事务的生成程序遇到执行异常会终止，不提供可恢复状态的回滚保证；显式内核事务 API 未改变。尚未接入 SDF IOPATH 的安全切边、自动预测器、增量回滚或 Time Warp。

## 验证

472 文件冻结源本地通过 17 组配置、51 个实际程序、288 份完整捕获和 192 次完整编码流比较，覆盖 8 类 RTL 与 3 类 SDF 场景各三种后端。各信号的完整有序变化和物理时间线在串行、1/4 内核间核对；不要求独立信号间的全局交错相同。屏障探针确认两个生成分区确实在两个 OS 线程上重叠执行；另有 12 项拒绝检查。10 项内核/parser 回归及串行语言、dump-task 回归通过。

4 个实际生成程序的 macOS ASan/UBSan、1 个多驱动程序的 TSan 通过，分别有 32/4 份捕获与正常版本完整对照。关闭并行的 16 类可比较程序，其完整生成代码、语义 IR 和替换旧 runtime 后的预处理结果与冻结467一致；旧版会崩溃的层次循环用例单独保留，修正后通过重复语义遍历与 sanitizer。

新 VCS 运行覆盖独立过程、层次参数/匿名原语延迟和258位延迟三类 RTL，每类三次，1644 次物理位时间线比较通过。这不证明完整有序 VCS 调度等价，也没有新的速度比。Linux 同源13项已独立验收：288跨平台完整捕获、51份整个CPP身份和148份dump捕获通过，两份原始全量 SDF 关闭选项的整个GCC预处理也相同；未执行完整112项或Linux sanitizer。原始证据与复算入口见 [本批记录](../validation/m6-auto-rtl/README.md)。

后继473文件源接入单分区串行回退和无 `$finish` 快照消减。本地18配置/54程序、306完整捕获、204完整编码比较和21份完整串行回退身份独立审计通过。复制探针在实际双线程重叠执行时为0次，强制开启全局结束事务对照为18次；这是复制计数证据。安装后的编译器54份CPP/IR身份、6个无波形程序及3个事件预算错误对照通过。新增两个生成程序的 macOS ASan/UBSan共16捕获通过；另4个旧ASan/UBSan、1个TSan和三类VCS例的整个生成程序相同，复用已有执行证据。473的Linux三项定向及原始全量SDF回退身份任务正在运行，尚不宣称通过。见[后继记录](../validation/m6-parallel-fallback/README.md)。

## M106：独立分区的原生整数循环

无输出通道的分区不再安装 resolved-value 观察回调，因此满足原有四态、事件、波形及预算约束的原生整数循环可以运行。第一次配置正延迟输出通道时安装回调，继续禁止源分区借用原生值绕过消息通知；输入值仍在保守窗口边界交付。此改动不更改分区算法、前沿同步、结束事务或回放规则。

实际分区数应查看 `--emit-ir` 的 `parallel.partitions`，不能用请求线程数推断。M106 的 CPU/CRC/muldiv/AXI4/cache 原始 perf-kit 输入在请求 2/4/8 线程时均退化到单执行分区；计算和共同的零延迟依赖绑定在一起。独立四计算域的测量另列，不能代表这些原始用例的并行加速，见[记录](../validation/m106-intel-parallel/README.md)。
