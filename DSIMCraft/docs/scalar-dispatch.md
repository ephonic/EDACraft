# Scalar signal updates and constant case dispatch

M111 reduces single-core call and dispatch overhead in two places.

For builds without wide values or strings, the public `set(int,V)` and `drive(int,int,V)` interfaces forward the two scalar bit planes to an internal register-argument implementation. On x86-64, passing the 24-byte `V` object to the former out-of-line functions required stack argument traffic. The small wrappers allow GCC to pass the planes as integers instead. Resizing, two-state conversion, force handling, driver ownership/resolution, aliases, edge detection and all observer notifications still use the same implementation. Wide-value and string-enabled builds retain the previous argument path. `DSIM_REFERENCE_SCALAR_STORES=1` selects that path for differential testing.

Exact integral `case` statements with exclusively known constant labels and a common width at most 64 bits use a host `switch`. Label normalization follows the existing common signed/unsigned context. An unknown selector matches none of these known labels. Each key records the earliest branch and the number of distinct matching branches, so duplicate labels within one branch count once and duplicates across branches still trigger `unique`/`unique0` diagnostics. The emitted PC layout, original instruction steps, default branch and deferred diagnostic handling remain intact. `DSIM_RTL_REFERENCE_CASE_DISPATCH=1` selects the comparison path. Dynamic or side-effecting labels, X/Z labels, wider values, text cases, `casez`, `casex` and `case inside` use a comparison path.

These changes do not fuse scheduling regions, skip events or add worker threads. Reference-argument stores and an inner Active FIFO batch were also screened; the final implementation uses bit-plane arguments and leaves the scheduler unchanged because the batch candidate did not produce a stable improvement.

The vendor comparison also exposed a pre-existing difference in side-effecting comma-separated labels. VCS evaluates both labels of the matching item; the former generated C++ `||` skipped the second call. Such lists now materialize their values once before comparing, while later ordinary-case items remain unevaluated after a match. This alignment changes no generated code in the four measured workloads; their final emitted program hashes are checked again after the correction.

The permanent regression covers signed and mixed-sign matching, 64-bit keys, duplicate branches, unknown selectors/labels, side-effecting labels, automatic functions, wide/string fallbacks, two-state stores, force/release, multiple drivers and delayed continuous/NBA updates. It compares 30 complete ordered/settled VCD captures, 501 exact execution-budget/state pairs and six prediction accept/reject outcomes across serial, time-wheel and thread-requested execution. Three generated programs and the runtime kernel also pass ASan/UBSan. Detailed performance data and release checks are in [M111 evidence](../validation/m111-scalar-dispatch/README.md).
