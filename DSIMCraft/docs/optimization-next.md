# 下一轮性能优化候选

0.13.0 已实现共享编译门级 handler 和 alias 成员缓存，保留通用 RTL 闭包的可复制语义，并分别做单项与组合 A/B。结果见 [本批证据](../validation/m5-compiled-process/README.md)；收益不完全叠加，继续依据实际 profile 排序。模型专用直接回调已完成实验但未采用，详见 [真实设计评估](../validation/m5-model-handlers/README.md)。固定 Liberty 反相已单独验收采用，见 [专用化证据](../validation/m5-unary-specialization/README.md)；固定敏感列表也已独立验收采用，见 [等价边界](fixed-sensitivity.md)；其余候选未实现，不计入加速结论。

1. **删除不可观察的未连接输出。** 当前每个缺失/空叶输出仍分配匿名 net 并驱动，如大型 ff 网络未连接的 QN。只考虑 parser 为该单一 pin 新分配、ID 不在 Network 声明范围内、没有任何其他用途、不会注册波形的输出槽；不删除真实有名称的内部 net，不删除 GateState 的 q/qn。可用负运行时 ID 加 guarded drive，或按输出连接掩码复用求值函数；输入的悬空 Z 必须保留。首次初始化、多个 DUT、组合/三态/非互补 q/qn、全部有序波形和回滚须逐事件验收。
2. **固定一元操作码与标量求值。** 真实 300ns 活动前缀中，`unary(std::string, V, width)` 自身占约 4.45% 指令，另有字符串 compare/strlen/memcmp。门级 Liberty 的反相操作在编译期已经确定，优先验证直接生成 `inv(expr.size(1))`，保持显式宽度归一化及完整 X/Z 真值表；再评估 uint8 四态表达式与轻量采样参数，避免不必要的 V 值传递。一般 RTL 的其他一元运算保持原语义。固定反相已经实现并验收：真实设计固定 CPU 五次交替降低约 14.3%；uint8 四态表达式及轻量采样参数仍是后续候选。
3. **继续消除公共求值/常量。** 全部代数规则以四态和事件边界证明；不要将 Z 当作普通 Boolean，或假设 q/qn 总互补。组合锥融合先限定观察和反馈边界；带 SDF/specify 模式另外证明路径/脉冲语义。

0.13.0 的 1 万 ff Callgrind 自身指令归因：gate sample 约 20.0%、set 12.0%、共享 sample handler 11.8%、run_to 10.8%、drive 9.2%。这些不是独立可叠加的墙钟收益上界，也没有硬件 cache 数据。该旧合成负载 profile 继续保留；新一轮主要根据实际 barr_modmult 的热点决定，以正常未插桩 A/B 决定是否合入。

0.12.0 的 `output_reads_inputs` 只参与顺序模型的输出消除；在推广为通用组合依赖元数据前，需补齐结构 copy/assign 的标记与测试。后续不要把不适用的组合项当作常量。

每项先保留候选源码、与固定原版生成模型/相同库的 SHA、独立真值表与有序事件，再保存预热、交替运行 CPU/墙钟/RSS。采用实际非规则反馈和普通 RTL/多驱动用例，避免只优化 INV 链或当前单一基准。

波形路线另测信号 ID 差分编码与块大小/检查点布局。0.12.0 的 1,921,765 条值事件，绝对 ID 的原始 varint 共 4,184,245 字节；沿原顺序连续使用 ZigZag delta 估算为 2,934,895 字节。该数值未包含跨块重启、模式字段和熵编码，不是压缩文件缩小或运行提速结论。先实现独立可解码候选，保持 ordered 的事件顺序、别名与四态，补窗口/损坏/回滚测试，再比较实际 CPU、RSS、字节数；不要只调高 Zstd 级别。settled 的分组位图候选须明确采集语义，不能套到 ordered 模式而丢弃变化顺序。

实际设计补充：128 组 golden 的 CPU 中位数当前 13.78s、VCS 6.14s，约 2.24 倍；直接模型回调为 13.77s，组合小负载持平、固定 CPU 反馈负载更慢，已撤回该候选。真实源只有 77 个新匿名输出 net /335,872 net，移除悬空输出可直接减少的状态很少。后续保持真实设计为主基准，合成网络用于覆盖特定结构。

真实 0.13.0 的 300ns 活动前缀 Callgrind：set 自身约 13.53%、drive 11.80%、组合 handler 7.26%、run_to 6.48%、unary 4.45%。普通/插桩运行均核对同一前 6 组 golden。Valgrind 的 brk segment overflow 警告原样保留，这些是指令归因，不是 CPU 百分比或硬件 cache 计数；源与日志见真实设计评估中的独立 profile 归档。

已采用的调度优化：编译门级进程的敏感列表在 elaboration 后固定，原 `arm_wait` 每次遍历全部 watch 并写 generation，现使用固定列表模式。只允许终生单一列表的编译进程使用永久敏感槽，原 set 唤醒判断不变并保持 Active/NBA 顺序；一般 RTL 的动态等待和多个 site 继续使用原 generation 协议。非法切换列表/延时会被拒绝，检查点、多个 context、反馈、别名、完整有序流和并行线程检查通过。同核真实 CPU 降低约 22.9%，RSS 降低约 19.3%，普通 RTL 基本持平，见 [原始证据](../validation/m5-fixed-wait/README.md)。

下一阶段同时推进可回滚延时驱动与实际 SDF 回标；性能侧继续按新 profile 检查四态值传递/drive 和功能模式下完整 Liberty 的处理成本。原版/候选/VCS 均须保留相同库与原始 SHA，不能通过先行简化 Liberty 或网表冒充对原完整输入的优化。

延时驱动内核基础已验收，尚未自动回标。随后重复单驱动写入候选通过完整正确性验证，但首轮真实收益 4.54% 未复现：同二进制五次配对 CPU 13.25→14.41s，五对均慢；fanout 两轮也略慢，已恢复原运行时。[本批记录](../validation/m5-redundant-drive/README.md) 保留源、原始计时和独立回归。该轮原版/VCS 14.32/10.29s（约 1.39 倍）不是新增优化结果；不混算此前不同轮次。下一项优先检查标量四态值传递与解析成本，先做独立 A/B，避免把更多判断放到每次全局驱动上；完整 Liberty 的读取/建模成本与仿真 CPU 分开验收。

标量四态表达式两版均已评估、不采用。第一版真实五次配对 14.54→14.55s；第二版改用组合位平面/归一化采样后，主轮 17.84→11.77s 看似改善，独立五次配对却为 13.20→14.48s，反馈 5.37→6.90s。普通 RTL 机器码和只读常量逐字相同，不能将主机波动归因于代码；全部样本及恢复见 [证据](../validation/m5-scalar-logic/README.md)。生产源已恢复。下一项按 [紧凑信号/驱动存储计划](compact-gate-storage-plan.md) 减少实际内存访问；真实内部非端口网 334,586 个中有 334,255 个单叶驱动，但这不免除额外手工驱动、alias、原子 copy、观察与恢复的语义验证。第一版完整两平台正确性通过，但真实五次配对 14.48→14.37s（仅 0.76%），未达到真实 CPU 门槛，已恢复已验收后端。反馈改善和真实 RSS 减少约 17% 保留为证据。下一版在隔离源中合并单驱动状态更新与变化发布，减少重复查找及 V 转换，按完整原网表筛选后再决定全回归和采用。

紧凑/合并驱动后继已验收采用，真实配对 CPU 减少 16.63%、RSS 减少 17.17%，反馈 CPU 减少 22.88%，详见[完整记录](../validation/m5-compact-drive/README.md)。下一性能项先采新后端真实活动前缀 profile，再决定读取值、watch/队列布局与安全的组合专用化顺序；不沿用旧热点百分比或把已失败标量候选直接重启为默认。单独测生成/编译/仿真成本，保留多驱动/alias、所有有序观察、恢复及 SDF 路径边界。

小型组合输出四态查找表已采用：真实七次配对收益中位数3.86%，6/7改善；反馈配对慢1.23%，保留负载边界。实际编译器新三方CPU为10.11/9.64/7.76s，LUT约为同轮VCS的1.24倍（零延迟/无波形/单核）。179,648组四态/别名与有序通知、两平台各30项和实际生成回滚sanitizer通过，详见[查找表说明](gate-four-state-lut.md)。下一步按新后端重新评价表达式复杂度筛选、实例常量传播及通知/队列成本；多输出共享读值必须先证明输出到输入的别名边界。
