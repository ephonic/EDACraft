# perf-kit RTL runtime optimization (M105)

The original report is preserved in `validation/m105-runtime/REPORT-PERF-original.md`. Exact original workloads and source hashes are in `tests/perf_kit`. Current measurements, raw evidence identity and release receipts are in `validation/m105-runtime/README.md`; historical synthetic arithmetic figures do not describe these workloads.

The implementation removes generated unary-operator string dispatch, expands replicated single bits directly into both four-state planes, and separates infrequent ready-queue allocation from the ordinary append. It also extends guarded native integer loops to logical shifts, valid constant slices and single-bit replication, and uses that path inside non-suspending functions. Shift counts of 64 or more explicitly produce zero; unsigned host arithmetic avoids signed-overflow and shift undefined behavior.

The native loop requires known bits and unobserved variable storage. Events, wave capture, force, timing/property observers, mixed aggregate state and dynamic activations retain the ordinary four-state process path. The existing exact instruction budget and partial-state writeback apply to function loops too. This does not fuse event regions or change NBA/port delta ordering. No benchmark names or CRC polynomials appear in the optimizer.

Validation includes an independent bitwise oracle over scalar/wide unary operations and X/Z replication, all related kernel regressions, automatic-function known/unknown inputs, shift counts 0–65 and huge counts, signed slice extension, native/fallback exact budget and state comparisons, serial/wheel/parallel wave captures, and accepted/rejected prediction. ASan/UBSan cover the unit oracle and actual generated function program. VCS checks the same function source and the original end-to-end workload checksums. The report's cache/VCS noncompletion is not assigned a cause or used to claim a timing ratio.

Rejected experiments included splitting signal writes into a separate notification routine (CPU slowdown) and skipping unchanged net-driver resolution (small mixed gains did not justify broadening this patch). Their screening figures are not final performance claims. Performance is measured with wave capture disabled; observer fallbacks prioritize simulation semantics.

M142 removes the stack-based scalar `V` transfer at whole-variable NBA commit, passing the stored planes directly into the shared publication path. Fixed-core Intel O2/strict/xHost/pthread full-workload medians improve CPU 9.60→9.12s (5.0%), CRC 4.77→3.48s (27.0%), muldiv 9.06→8.01s (11.6%); AXI4 remains 0.19s. CPU still takes about 1.60 times VCS CPU time on this server. The [M142 report](../validation/m142-nba-payload/README.md) records exact flags, original inputs, all samples, semantic checks, rejected candidates and dual stable publications. These ratios cover these workloads only; no suite-wide performance or complete VCS feature parity is implied.
