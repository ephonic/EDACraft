# 逐接收 pin INTERCONNECT：运行时与 VCS 语义依据

本轮已实现常用INTERCONNECT运行时，验证与边界见[运行时](sdf-runtime.md)和validation/m4-interconnect-runtime。下面保留实现前的语义研究记录。以下为实际VCS W-2024.09默认选项的观察，不是完整标准或其他模式的兼容声明。13组各独立编译、三次运行，完整trace与全部声明的稳定态位波形一致；每例首次注解日志0 errors /0 warnings，记录MIPD approximation `MAXIMUM`、pulse_r/e均100。后两次运行使用VCS缓存，不声称有三份独立注解日志。

## 已验证的差别

- 同一源网到两个接收输入有不同延时。3/4/6ps与9/11/13ps的接收端分别变化，源网立即变化。必须建立私有接收pin值，不能给共享net统一加延时。
- 按接收模型precision量化。接收precision10ps时，4/6ps变成0/10ps，5/15ps变成10/20ps；仅源模型precision改为10ps、接收仍1ps时，4/6ps保留。
- 本组输入延时按新值选择：1用rise，0用fall，Z用turnoff，X用三者最小。它不是现有IOPATH的前后转换查表。两个值的turnoff取rise/fall最小；本组十二值INTERCONNECT只体现前三值的行为，后九值没有成为独立转换延时。不能把IOPATH的十二值/X推导直接复用到MIPD。
- 默认正脉冲测试中，7ps rise接收端拒绝1/4ps脉冲，保留8/12/30ps；11ps接收端另拒绝8ps，保留12/30ps。fall分别19/23ps；尚未覆盖负脉冲、恰好等于延时的边界或其他pulse选项。
- 多源默认MAXIMUM：两个源各3/10/6与9/4/12ps，接收有效rise/fall/off为9/10/12ps，X为9ps；反转注解源顺序结果相同。这区分了“先逐项MAX再取X最小”与“先各求X再MAX”。
- 同源同接收端重复ABSOLUTE会覆盖：先3/4/6再9/11/13得到后者，反序得到前者；不能把所有ABS记录一律求最大。
- 多源已有3ps与9ps后，对3ps那条源记录INCREMENT20ps，实际接收变成29ps，不能只算该源3+20再与9取最大（23ps）。实现必须区分按源记录、当前有效MIPD及有序读回更新；更多稀疏/混合更新仍须补参考，不能凭此一个例子推导完整算法。
- 单源2+4−9+6ps最后为6ps，证明负增量逐次夹零；输入互连5ps再输出互连7/11ps分别到12/16ps。全局tick为1ps。

原始输入、编译/运行/注解日志、ELF及daidir依赖、39份VCD、独立解码与哈希见`validation/m4-sdf-interconnect`。可复用的输入生成器和完整位参考在`tests/sdf_interconnect`。原研究批次本身没有native对VCS运行时匹配、真实全量SDF或性能验收声明；后续运行时接入验证另行记录。

## 有序更新补充：物理源数量影响 ABS

追加12组更新微例与4组结构驱动数对照，各独立编译、三次运行。完整核对见`validation/m4-sdf-interconnect-updates`，原13参考与归档保持不变。以下是当前默认VCS模式在这些输入上的观察，仍不是完整算法或native功能声明。

- 两个物理驱动已有有效9ps，对任意一条源INCREMENT −7ps均得到2ps；已有29ps再对另一源−7ps得到22ps。因此增量读取和修改的是当前接收有效值，不能更新一张按源独立延迟表后再MAX。
- 双驱动已有9ps，再对任意源ABS 4ps仍为9ps；增至29ps再对任意源ABS 4ps仍为29ps。ABS不能通过替换一条源的历史值降低接收有效值。
- 四组控制确认与物理结构有关：只注解src/Z这一条源，单物理驱动ABS 9→3得到3ps，双物理驱动得到9ps；ABS3、INC20、ABS4在单驱动得到4ps、双驱动得到23ps。另一个物理驱动始终驱Z仍影响这个规则；不是数“出现过多少条SDF源记录”。
- 双驱动有效rise/fall/off=9/10/12ps后，ABS `(5)()(8)`得到9/0/12，X为0；空位置会清除该分量，不能当未更新或普通MAX零项。INC `(20)()(-2)`得到29/10/10，X为10。
- 同样基础上，TYPICAL选取INC `(20::)(:2:)(::4)`得到9/12/12：缺失所选corner没有增加对应分量。完整missing-corner ABS、显式零和不同精度交错更新仍须进一步区分。
- 六值列表`3/7/11/13/17/19`本例有效前三项3/7/11，X3；典型corner三项各自选择得到3/4/9，X3。没有把IOPATH六值/十二值转换规则借给MIPD。

这批参考决定数值状态应首先围绕**接收有效值和真实结构驱动数**设计，源记录用于严格绑定与定位，不能预设每条记录拥有独立可降低的延迟历史。稀疏值具有专门语义；实现前仍需补不同corner、显式零、量化先后及alias/顶层端口等结构来源边界。

## 接入检查项（实现前规划，1–4已接入常用范围）

1. 门级预处理已接入并验收，仍走独立结构parser。最初合法`timescale头失败的证据保留在旧目录；新增验证没有删原始头，13份原始网表现全部到达明确INTERCONNECT运行时拒绝。宏/include依赖、原始行诊断、覆盖保护及实际结构scope时间已验证；普通大网表采用无token/逐行表的快速路径。详见[门级预处理](gate-preprocessing.md)与validation/m4-gate-source。此项不代表互连延时已执行。
2. 新建MIPD数值与接收有效注解状态，按真实结构驱动数区分ABS更新；源端点记录保留绑定身份，不按独立源表MAX误推有序读回。绑定沿用当前严格拓扑/端口检查，按接收模型精度处理更新；追加参考已覆盖部分稀疏/交错/六值情况，仍补missing-corner ABS、显式零、量化先后和溢出。不能借已有IOPATH表的通过结果替代输入延时验证。整文件成功前不提交部分源/IR。
3. 每个受影响的接收输入分配私有延时net与驱动通道；模型输入、固定监听和IOPATH因果时间均读取该私有pin。物理源网、其他接收端和驱动身份保留，输入/输出互连与非零IOPATH串联必须覆盖。分离输入延时的值选择和IOPATH转换选择。
4. 检查点拥有所有输入通道、取消generation、前值和待交付事件，覆盖首次建立、待交付中失败预测、接受提交及相同边界的完整ordered/settled波形。波形字典须明确表示私有接收pin，不错误别名到物理源网。
5. 两平台、实际ASan/UBSan、四态/多驱动/零延时/delta/反馈/窄脉冲、13参考及追加参考验证后，再测未改真实网表和全量flattened SDF；timing checks只有显式禁用才可跳过。COND/PORT/DEVICE等未完成项仍保持明确边界。
6. 将实际正延迟接收图作为自动保守分区的基础。舍入为0的边与SCC必须正确处理；手工ConservativeSim和手工预测API不等同自动并行或自动预测器。性能优化仍独立配对验收。
