# RTL 与门级网表的独立前端

RTL 与门级网表使用不同的 parser 和适配层。它们只在拥有数据的仿真 IR 汇合，随后共享四态运行时、事件调度和编译后端。

0.8.0 的 `src/preprocessor.cpp` 只在 RTL/测试平台入口执行，展开文件列表、include 和宏，输出文本、依赖和逐行源位置。结构门级文件仍直接送入专用 parser；若同一个文件还被作为 RTL 输入或 include，则在进入 AST 前拒绝。预处理和文件列表资源限制、输入路径保护与语法/编译诊断映射不依赖门级 Network 的节点。

后续波形后端通过拥有数据的信号表和 resolved net ID 注册，不通过重新解析门级源码查找名称。编译时按 dump 范围在释放 Network 名称前导出层次和别名；运行时共用 writer。独立可解码原型、分块熵压缩及百万信号扩展计划见 [波形设计](waveform-format.md)，当前原生运行时尚无 dump 功能。

| 路线 | 输入和职责 | 规模策略 |
| --- | --- | --- |
| RTL | token 预处理 → `dsim_rtl_parser` → AST → 层次、参数、行为和类型展开 → 仿真 IR | 优先语义覆盖与明确诊断；每个参数实例独立专用化 |
| 门级 | `gate_netlist_parser.cc` → Network → 单元/引脚/网络绑定 → 仿真 IR | 简单结构语法；紧凑连续表、整数 ID、名称池，避免构造行为 AST |
| 单元模型 | Liberty 功能模型或经过 RTL 前端编译的 Verilog cell model | 同一单元模型复用，实例保存连接和必要状态 |
| 激励 | 测试平台经 RTL 前端编译，与门级设计的端口绑定 | 不将整份门级设计重新送入 RTL parser |

当前 `dsim` 的 `compile_rtl` 接口与 `src/rtl_compiler.cpp` 只处理 RTL；门级 parser 已是独立的第三方库组件，现通过 `--gate-netlist` 解析、严格检查及绑定到独立的紧凑 GateDesign IR，再连接 RTL 测试平台。已接入 Liberty 组合及单状态对 ff/latch 的零延迟功能，大规模吞吐、编译及仿真性能分别测量，不代表完整门级支持。

M3 的独立入口位于 `src/gate_compiler.cpp`。Network 的网、单元、引脚绑定到拥有数据的 GateDesign 表，连接使用整数 ID；未绑定单元明确报错。网表连接不克隆完整 cell AST，参数化行为模型在专用化后可按模型复用。禁止为求统一而把门级 Network 转回 RTL AST。

大规模验收需使用可重复生成的 10 万、100 万等实例级别网表，以及实际网表语料；分别记录读取/解析、名称绑定、连接表构建和编译生成阶段的时间、峰值 RSS、实例/引脚/网数量。parser 吞吐基准不包含 C++ 编译或仿真时间，仿真端到端基准单独报告。名称保留、字符串驻留、批量分配和模型复用按实测决定；现有 10 万/100 万实例规则 INV 网表的分阶段计时、进程 RSS 和编译/运行基线见[门级验证记录](../validation/m3-gate/README.md)，实际网表性能仍待测量。

RTL 当前的实例化采用两步：先收集全部实例和声明，对同宽完整 net 端口做等价集合并；再生成方向性端口适配器和各实例行为进程。这样可保持 inout、网冲突、释放 Z 和输出端口内部读回语义。不同 packed 下标范围保留各作用域的索引映射。`--emit-ir` 导出实例、参数位串、作用域信号 ID 和端口连接类别，用于检查展开结果；运行期不使用 parser 节点。

## M2 第二批的左值与按位连接

左值使用独立 `LValueIR` / `PartIR` 片段，记录信号、位偏移、宽度和 RHS 偏移；不把 parser AST 放入运行时。重叠变量拼接按 VCS 实测从左向右提交，因此右侧项最终生效；该行为与 Icarus 不同。部分 NBA 捕获 RHS，在 NBA 提交时合并各变量的最新值；连续赋值片段以 Z 填充未驱动位，再统一解析。

RTL 当前将同宽 net 的完整引用在编译期合并；选择连接及 input/inout net 拼接以稀疏按位等价组连接。output 拼接仍使用方向性适配器，覆盖前批 VCS W-2024.09 常量专例。M3 第二批的动态输出探针显示更广的逐位 net 折叠行为，常量驱动还存在默认/debug 配置差异；门级前端已按动态连接结果实现，RTL 对应覆盖与修正继续推进，不能将前批有限专例推广为一般 output 语义。直接选择输出 net 的内部读回与 Icarus 存在差异，两组原始输出继续保留。

只有参与片段连接的 net 位才构建等价组，完整连接仍使用原有编译期合并；无关的普通 net 保留直接解析路径。这是按位别名的正确性基线，其大规模吞吐与内存尚未独立测量。门级 parser / Network 入口继续独立，后续可复用这些拥有数据的连接和驱动描述。

## M2 第三批的过程控制流

过程 for/while/do-while/repeat/forever 使用 IR 的条件跳转和回边，运行期执行，编译期不展开循环体。repeat 为每个语句分配独立的进程捕获计数，入口求值一次，嵌套及 delay/event 挂起后仍保持各自的剩余次数。每个生成指令计入执行预算。

case 在入口捕获一次选择值，以所有标签的共同上下文位宽生成顺序匹配；普通 case 比较四态精确值，casez 忽略任一侧 Z 位，casex 忽略任一侧 X/Z 位。选择分支后直接进入该分支状态，挂起恢复不重新选择；default 只在所有普通标签失败后执行。分支表达式都参与 @* 读集合。

原 RTL parser 的过程节点原本尝试常量选择/循环展开；现在过程节点只绑定全部表达式和分支，执行由编译后端承担。generate 继续使用自己的节点类别，不与运行时循环混用；专用门级 parser 没有改动。

二元表达式代码生成使用 `binary_op<Binary::...>` 将运算符固定为模板参数，使本机编译器消除无关运算分支并内联所选运算。四态与上下文位宽仍使用相同值表示和规则；动态字符串入口只作为运行时 API/单元测试入口保留，生成模型不调用它。性能变化通过相同算术循环及事件/NBA 负载实测，不能从单个内核推断整体 VCS 性能。

## 值类型事件与固定等待位置

生成模型在全部进程注册后、首次运行前登记每个固定等待位置。每个位置保存进程 ID 及一段紧凑的信号/watcher 槽位索引；`arm_wait` 只递增进程代次并更新当前槽位，其他位置的旧代次不会唤醒进程。watcher 数组不删除槽位，追加或扩容也不会破坏整数索引。动态 `wait` API 使用独立缓存槽位，与固定位置共存，不在每次等待中删除其他槽位。

Active/Inactive 使用可复用的环形值队列，区分直接执行与 delay 唤醒后入队，保留原有两步入队和去重顺序。NBA 使用拥有值/左值片段的记录及两块复用批次存储；全信号写入不创建闭包，部分写入仍捕获拥有数据的片段并在提交时合并最新值。非零 delay 使用按时间/插入序号排序的最小堆，同一时间按原入队顺序转入 Active。这些改动不引入并行执行或改变 Active/Inactive/NBA 分区。

当前分配测试只承诺已预热的基本 clock/edge/完整 NBA 路径不再产生 C++ 堆分配；部分 NBA 捕获、多驱动/按位解析和队列首次增长仍可分配。门级 parser 与大网表存储仍按独立路线推进，不能将这一调度优化解释为真实大规模门级设计的性能结论。

## M3 首批组合门级绑定

GateDesign 不持有 Network/RTL 节点。一个模型保存一次 Liberty 输出表达式，每实例只保留模型 ID 和连续 pin 表的起点；Network 的完整名称及查找表在绑定返回时释放。生成的 C++ 每种模型有一个求值函数，连接用静态数组保存，各 DUT 的运行状态单独分配。源网表实例数量不会增加 RTL parser 的 AST 数量。时序/波形路线需在名称释放前完成 SDF/SPEF 绑定，或按需保留名称索引；当前精简策略不代表放弃这些后续目标。组合门在写输出前重新 arm 输入，以保留自身输出反馈产生的下一次 delta 事件。

绑定按 Liberty 的实际 pin 方向遍历全部引脚，不使用时序 Network 的单一 driver 字段作为驱动来源，也不沿用未知 blackbox 的推测方向。每个输出引脚分配独立驱动 ID，因此同一单元的两个输出接到同一 net 时也能正确解析冲突。

RTL parser 只接收 DUT 端口桩和测试平台。展开桩时记录实际端口信号/位偏移，并在 RTL 进程与等待登记后安装门级进程；全部 net 位连接完成后才统一启动调度。这样避免门级插入改变已有 RTL 进程/等待编号，并保留端口的多驱动与四态解析。

门级原 parser 可为时序图近似跳过表达式及过程块，因此仿真显式开启独立的严格 grammar 检查；不支持的输入在 Network 生成前报错。输入文件只读一次并复用 source view，严格检查按 token 流进行，不建立行为 AST。后续结构宽连接及 Liberty 状态单元增量见下文；门级输入中的过程块仍明确拒绝，接口边界见 README。

Liberty 布尔函数按反相、XOR、AND、OR 的优先级编译，支持前/后缀反相、显式及隐式 AND、常量和括号；three_state 为高有效禁用条件；未知禁用条件保守驱动 X，即使数据为 Z，也不使用表达式 mux 的相同 Z 合并规则。这一门级规则来自首批 VCS 探针与穷举差分。依据 [Synopsys Liberty 2017.06 用户手册第 4 章](https://usermanual.wiki/Document/LibertyUserGuidesandReferenceManualSuiteVersion201706.163045249.pdf) 的 function 运算符表；混合优先级用独立加括号的 Verilog cell model 对标。inout cell pin 及缺少输出 function 等明确拒绝。首批将 three_state 写入 FTLib v13 的追加字段，保留 v5–v12 读取，旧版缓存该字段缺省为空；本批缓存升级见下文。

## M3 结构宽连接

仿真模式在 token 流上将一个当前连接直接展开为 MSB 优先的位名称列表；列表在绑定后释放，不保存表达式/模块实例 AST。部分选按声明方向检查，支持内部升序/降序范围；复制次数、常量宽度和索引都有显式上限。门级顶层端口仍受 RTL 测试平台 1–64 位 unsigned packed 限制。

Liberty 在建网前提供真实引脚方向，标量叶 pin 可截断宽输入、扩展宽输出。结构模块的 net 端口按低位对齐建立逐位别名，保留外部驱动对内部读回的影响。输入的数值常量和补齐位使用局部驱动，不允许内部写输入反向污染全局常量 net；输出多余高位独立驱动 0；inout 当前要求同宽。空模块也有独立未驱动端口网。常量输入和动态输入连接重复输出时，VCS 优化配置存在实测读回差异，详见[门级连接记录](../validation/m3-connections/README.md)，不使用按用例名称决定行为的实现。

多位 assign/适配器按宽度复用 `__dsim_copy_N` 模型；每实例只保存标量网连接表。`drive_copies` 先写入全部独立驱动，再统一解析受影响网及按位别名，读取同一旧 RHS、避免重复目标的中间状态触发事件。可覆盖超过 64 位的内部结构赋值；这不会改变 RTL packed 值的 64 位上限。Liberty 原有组合求值函数仍按单元类型复用，门级输入等待继续先 arm 再写输出。

`parse_seconds` 包括读取、metadata、严格语法/宽连接展开和 Network 构建；`bind_seconds` 包括提前执行的 Liberty 读取/方向收集与后续模型/引脚绑定。两阶段均由同一 `--gate-check` 进程测量，RSS 是整进程峰值；与前批比较时应保留阶段定义及源码快照。

## M3 Liberty 状态单元

Liberty parser 独立保存 ff/latch 类型、两个状态变量、时钟/使能、下一状态/数据和异步控制属性。GateDesign 将表达式编译为每模型共享的采样函数和输出函数，状态变量引用直接读取实例的 GateState；实例连接仍是整数 pin 表。只有时序实例分配状态槽，每个槽保存当前/待提交的两个四态位和控制历史；本次 LP64 构建 sizeof 为 20 字节。RTL AST 的大小不随门级单元数量增长。

采样进程在 Active 先重新 arm 依赖，再计算控制和待提交值；存在状态变化时登记值类型 NBA 唤醒。提交进程在 NBA 批次之后执行，把状态写入并求值输出，锁存反馈还需重新调度采样。下降沿或同刻保持事件保留已捕获的待提交值，未知异步控制各分支使用同一旧值快照。输出函数若依赖普通输入，采样时也求值，以维持 Active 响应。仅依赖状态的输出目前同样被重复求值，后续可按表达式依赖消除无效求值，但须保留事件阶段和独立驱动语义。

FF 的等待集合只包含时钟、异步控制和输出函数/three_state 的实际输入依赖，数据仅在触发采样时读取；latch 另包含 data_in 依赖。Boolean 时钟的每个输入都参与等待，因此 enable 在原始时钟不变时改变派生时钟也会触发。IR 导出状态实例数、状态位数和每模型等待 pin 数，规模检查同时确认只有两个 RTL scope 和按模型共享的 C++ 函数。

初值 X，存储 Z 归一化为 X；未知边沿、使能和异步控制按可能结果共识合并。两个状态位独立，clear/preset 冲突按 L/H/N/T/X 分别处理。当前为理想功耗、零延迟模型，不能据此推断任意 foundry UDP/notifier 的未知传播或时序等价；bank/statetable、多个状态组和双时钟/使能明确拒绝。最小事件阶段探针、失败记录与独立参考见[时序验证记录](../validation/m3-sequential/README.md)。

FTLib v14 在 v13 布局末尾追加每 cell 六个 uint32 字段，plain/gzip 及 ID 重映射采用同一布局；保留 v5–v13 读取，旧缓存缺失的类型/状态名不凭空推断。多库 loader 在读完库目录后重新取得指针，防止库容器扩容使早先指针悬空。本批相较 0.6.0 只修改三个第三方 Liberty 文件，独立 gate parser 和全部 RTL parser 字节不变。
