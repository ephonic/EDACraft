# 后续性能优化的执行顺序

性能为主线，按同一设计、同一配置与 VCS 对照；RTL、门级零延时、SDF 和波形分别测量。最新同配置门级零延时、无波形真实设计：默认 CPU 中位数 12.38s，VCS 10.48s，约 1.18 倍；可选 batch 为 12.15s，约 1.16 倍，默认关闭。见 `validation/m5-fifo-batch`。最近包含 VCS 的完整原始 SDF 五轮测量为旧基线 125.69s、紧凑接收端 113.48s、VCS 9.22s；紧凑接收端/VCS 约 12.31 倍，随后独立复测通过并默认采用。后继标量交付独立五对配对耗时下降中位数14.63%，CPU中位数111.15→94.89s，默认仍关闭；该复测没有新VCS分母。见 `validation/m5-compact-inputs` 和 `validation/m5-scalar-timing/replication-verification.json`。时间轮和SDF专用作业已通过两平台功能验收；两者与标量基线及VCS的同轮消融脚本见 `validation/m5-sdf-ablation`，已终止并独立核对PASS：组合80.31s/VCS7.47s，候选耗时约10.75倍，组合配对改善10.73%待独立复测；单独wheel回退6.30%、jobs改善0.22%，均默认关闭。功能子集扩大前后，不直接混算用时。下文保留各批筛选历史，当前差异归因见 [performance-gap.md](performance-gap.md)。

1. 在已采用紧凑网 / 合并驱动 / 四态 LUT 上重新采活动前缀 profile，同时核对真实 128 组 golden。区分初始化、稳态求值、解析驱动、通知 / 队列和内存读取；不能沿用优化前的热点占比。
2. 首先减少通知和队列的重复访问，然后评估每个输出函数的计算专用化。独立改变一项，保留原程序作为基线；同核交替配对，实际 CPU 为主，同时记录墙钟、RSS、代码与编译成本。
3. 对等价变换引入明确的语义边界：四态值、驱动身份、初始状态、事件区域与可观察的输出顺序必须保留。时序弧、反馈、三态、多驱动、波形可见点均是必须检查的边界。组合锥合并或常量替换不能因为稳态输出相同就删除初始 / delta 事件。
4. 只有真实设计至少 3% 的配对收益稳定复现、反馈中位数回退不超过 3%，且功能 / 有序波形 / 回滚验证通过，才进入默认后端。共享主机波动全部保留，不以最好一次或更少的代码作为采用理由。

当前 LUT 后端已重新采完整初始化及300ns活动前缀：按函数聚合self Ir，通知publish_compact为15.42%，drive为13.58%，run_to为10.90%，ReadyQueue::push为6.09%。这是指令归因，并非CPU比例。见 `validation/m5-lut-profile`。

本轮三个方向均未采用：紧凑网直接编码读取的真实五对收益中位数0%；队列扩容移至冷路径仅1.70%；固定监听压缩及网槽对齐虽在真实设计改善5%–6%，却在100k触发器反馈回退8%–12%。所有原始样本保留，默认后端未叠加这些变换，没有新的VCS性能比例。下一候选优先保持原48字节紧凑槽，以互斥存储减少固定监听成本，先解决时序负载回退，再考虑组合求值融合。见 `docs/compact-fixed-watch-plan.md`。

追加两项也未采用：复用解析后备的48字节监听表示，真实五对配对收益2.74%、反馈回退5.76%；LUT基线只专用化组合handler，真实−0.33%、反馈−0.51%。见`validation/m5-watch-reuse`及`validation/m5-lut-model-handlers`。前者本地38项及实际sanitizer/回滚波形，后者实际编译器37项/11份生成程序变换一致，均不能替代性能门槛。下一性能方向应评估批量发布/驱动解析中的固定拓扑预计算，先量化真实活动与反馈的调用分布，避免再单凭布局或少一次间接调用推断收益。

功能方面，有限无条件IOPATH已接入实际编译CLI并通过两平台37项、新VCS路径微例和实际波形/回滚验证。下一步接逐接收 pin INTERCONNECT 和 timing checks，再从真实正延迟图推进自动分区。COND、pulse/RETAIN和全量真实SDF仍未完成。波形继续以独立可解码、窗口访问和完整信号规模验证为验收条件。

独立门级预处理已验收，默认构建更新；它没有修改已采用runtime或模型求值。完整真实设计（原始网表+既有64位封装、独立RTL激励）旧/新实际编译器生成的整个C++逐字相同，新增扫描31.6MB的单次成本约0.252s；这不是仿真收益。两平台各39项、宏/include+有限SDF实际sanitizer及预测波形已验证。后继性能筛选须以这一已验证实现为基线，等待Linux构建/前端观察全部结束后再开始计时；此前失败候选继续不采用。

固定拓扑实测已完成：真实非零时刻61,209,513次扫描中11,851,282次目标已不等待，反馈18,545,776中4,615,892次；代际/边沿过滤均为0。纯fixed-any属性缓存保持48字节槽和16字节Watch，初筛真实4.07%/反馈1.81%，但独立七对真实仅1.86%、4/7改善，反馈1.96%，未达门槛，不采用。计数不是CPU归因，不能据此承诺减少重复扫描的收益。

后继优先评估有严格拓扑边界的执行融合：先统计单输出、单扇出、非SCC组合链及真实活动次数，再选择是否值得生成专用链代码。融合必须保留原FIFO位置、单元内输出顺序、重新等待时点和每次step计数；延迟/边沿/反馈/三态/多驱动/别名/可观察点作显式边界。无法证明事件顺序相同的链仍用现有调度器，先做完整有序波形与回放对照，再进行独立性能筛选。避免继续仅凭少一个分支或布局变化预计收益；本项还未实现或采用。

静态候选边普查进一步限制了方向：真实130,072条单输出/唯一监听/紧凑网的组合候选连接中，只有166条进入单输入单元，59,517/69,774条进入二/三输入单元；反馈为0条。完整紧凑网数、监听数和度分布与实际runtime计数相同。简单单输入链覆盖太少，不先投入完整融合实现；多输入融合须先证明其他输入已有排队任务时的FIFO语义。候选边不等于安全融合边，未测活动比例或收益。见`validation/m5-chain-inventory`。

FIFO批量执行现已作为显式--gate-batch入口接通：相同handler/context的就绪前缀顺序执行，配原生模型switch，保留每次驱动、fixed rearm、step、其他队首任务和SDF/波形/回滚语义。两平台八组完整流与实际回放通过。真实原始宽接口设计五对配对收益2.26%，100k FF反馈3.41%；真实未达默认3%门槛，默认关闭，不再追加局部循环微调。测量使用本轮同一原始宽TB，不能与旧分块包装或不同仿真配置混算。详见validation/m5-fifo-batch。性能主线后续需在更高层的组合图/观测边界消减工作量，而非继续仅减少分派调用；整体工具先转全量SDF模型生成和分区/波形执行闭环。
