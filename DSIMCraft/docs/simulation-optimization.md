# 仿真性能优化（0.12.0）

性能优化与功能补全共同推进。0.12.0 首先减少驱动存储访问和可证明的重复输出求值；零延迟的 RTL/gate 调度、四态冲突、NBA 阶段及观察事件保持不变。当前不涉及带 SDF 的延迟、脉冲或 timing-check 优化。

## 单驱动内联

`DriverValues` 在 net 内保存第一个驱动的 ID 和四态值，其他驱动按需放入独立 map。常见单驱动路径无需分配树节点，也无需遍历 map 或与初始 Z 再做一次 resolve。第二个及后续驱动仍参与完整强驱动冲突解析；overflow 存储在检查点中深复制，不能把共享指针误作已保存状态。

这不是把 net 当作二态变量。128 驱动的混合位向量、所有标量四态组合/不同插入顺序/有符号驱动 ID，以及修改已有 overflow 和新增驱动后的可重复恢复，均有独立预期测试。对象大小和堆分配需合计衡量，不能只依据 `sizeof(Signal)` 推断 RSS。

## 状态输出的重复求值消除

编译 Liberty 输出 function 和 three_state 时单独收集输入 pin 依赖。若一个 ff/latch 的所有输出仅依赖其两个存储状态或常量，则输出仅在首次初始化与存储状态实际改变后求值。时钟、异步控制及锁存采样仍照常执行，NBA 提交阶段保持原位置。

证明条件是：存储状态未变、输出不读输入，故各输出驱动四态值不变；重复写相同驱动不会改变解析值或触发值变化事件。首次采样必须保留，因为初始 net 是 Z、存储状态是 X。若任一输出 function 或 three_state 依赖输入，则整个 cell 保留采样和提交时的原有求值路径。已有 DFFOUT 的组合输出和三态使能测试覆盖此回退，ff/latch 反馈和回滚也继续验证。

此规则只能用于当前理想零延迟模型。未来 SDF/specify 模式必须另外考虑路径事件、脉冲及条件依赖，不能仅用上述值相等证明跳过时序处理。

## 测量与后续变换

每项候选与固定旧版在同机以相同输入、编译选项、观察范围预热后交替测量，分别报告 CPU、墙钟、RSS 和生成/编译成本。每次运行校验独立期望；大基准的 64 位采样/checksum 不替代全波形等价性。功能回归额外比较有序波形和 VCS 参考。

第一轮单驱动实验，10 万触发器/200 周期的 CPU 中位数从 11.47s 降到 9.73s，同轮 VCS 为 4.91s；这些是单独候选的数据，最终组合优化结果见 [性能验证](../validation/m5-driver-inline/README.md)。共享主机未固定 CPU/频率，不把跨批历史差异作为代码收益。

最终五版本同轮比较：原版 13.32s、仅驱动 10.46s、仅输出消除 11.23s、组合 9.66s、VCS 5.28s。组合降低 CPU 27.48%，峰值 RSS 从 140232 降至 113500 KiB；CPU 仍为 VCS 的 1.83 倍。1 万触发器 Callgrind 指令总数由 5,224,238,018 降为 2,565,506,331；这说明执行指令减少，不等于相同比例的运行时间改善。剩余热点包括 gate sample、set、alias map 查询、过程闭包调用与调度队列，下一项候选须另做 A/B。

后续根据 profile 继续常量传播、公共表达式和组合区域融合。所有代数规则先按四态验证，不能把 `a ^ a` 无条件折成 0；组合融合还须证明边沿、毛刺、零延迟循环、多驱动与有序观察边界。一般 SDF、自动并行分区和完整 VCS 对齐仍按 [计划](../plan1017.md) 推进。
