# RTL predicates, parallel windows and checkpoint restore

The RTL compiler fuses pure one-bit predicates containing at least four operations into one native unsigned word expression. Each distinct input is loaded once and all its unknown masks must be zero. Otherwise the original four-state expression runs. Widths, signed comparisons and expression contexts use the existing integral lowering rules. Stores, process scheduling, NBA and instruction accounting remain in their original positions. `-DDSIM_RTL_REFERENCE_EXPRESSIONS=1` selects the reference expression for differential testing. This is expression fusion, not fusion of RTL processes or zero-delay evaluation regions. A broader arithmetic-expression candidate and PC-dispatch candidates were withdrawn after full-workload screening showed regressions.

For generated models with multiple independent partitions, `run()` now executes several event timestamps per conservative window. Previously its next-event horizon forced a synchronization at each timestamp regardless of the configured window. Workers retain their last real activity time rather than creating an idle timestamp at the end of a natural window. Natural completion aligns kernels to the design's last real activity. Explicit `run_until(horizon)` still advances to its requested horizon.

The runtime option `--parallel-window TICKS` sets the maximum natural window, in the generated model's physical precision ticks (default 1024). For example, with 1ps precision, `--parallel-window 1000000` requests up to 1us per window. Every positive-delay channel additionally limits the window to its minimum lookahead. Small windows improve responsiveness and bound buffered speculative effects; larger windows amortize synchronization and snapshots for independent domains. Single-partition fallback validates and accepts this option but has no parallel window to change.

Global finish retains transaction isolation, timestamp/partition tie ordering and rollback/replay at the earliest finish fence. Wave changes, printed output and virtual file effects commit through the existing transaction path. Committed natural horizons refer to real activity, avoiding a spurious final waveform timestamp. This uses existing bounded finish speculation; it does not introduce an automatic value predictor or optimistic cross-partition Time Warp.

Restoring a checkpoint still copies its immutable snapshot, including mutable RTL closures and queues. It now moves that temporary kernel into place instead of copying it a second time. Checkpoints remain reusable and registered model state is restored afterward. Snapshot capture itself still copies the full kernel; topology sharing, incremental undo logs and copy-on-write state are future work.

`tests/runtime_windows` compares complete ordered/settled value streams, exact exhausted-budget state and prediction accept/reject against reference expressions. It also exercises actual generated four-partition RTL across window sizes. `tests/parallel_natural.cpp` checks dense clocks, positive-delay messages, quiescent time, global finish, late speculative exceptions and continuation with an explicit horizon. The component benchmark measures independent event domains and repeated checkpoint restore separately from the original RTL/VCS performance suite. Component speedups must not be presented as speedups of shared-clock RTL: the original perf-kit designs still produce one execution partition.
