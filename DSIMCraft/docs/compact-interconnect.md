# INTERCONNECT 接收端的紧凑表示

状态：首轮五对配对 CPU 耗时下降中位数 8.13%、RSS 下降 16.66%；独立五对全部下降，中位数 10.20%、RSS 下降 16.32%，原始输出/计时已复算通过。两处配对改动现已默认采用；含全局结束协议的组合版本两端各 60 项回归、实际新编译器完整 SDF 生成身份和原始证据均核对 PASS。下文描述这一实现。

受 SDF INTERCONNECT 影响的输入仍拥有私有接收端，源网与其他接收端保持独立。此次改动只改变接收端存储和延迟驱动的注册方式，继续使用同一调度器、输入延时 handler、路径选择、时序检查与延时通道。

代码生成使用 `compact_net()`。单驱动值与解析值存放在紧凑槽中；延迟驱动注册读取 net 类型和宽度，不再调用会创建通用后备对象的 `signal_record()`。通用多字 net 不变，compact 遇到其他驱动或 alias 时仍可按原规则转入通用解析。

私有接收端在安装期间先设置 Z 再设置 X，与旧实现创建 net 后设置 X 的最终路径戳相同。两次设置发生在添加该接收端的监听、时序检查及波形启动之前；没有新增调度步骤。不能直接删去初始化转换：compact 槽原来初值就是 X，直接再设置 X 不会记录旧接收端在时间零的 Z→X 路径戳。

已有 compact 通知路径负责四态边沿、固定等待、路径戳、逐变化检查及波形；私有接收端的负信号 ID 由同一访问接口处理。取消 generation、已提交驱动值、待交付事件与输入前值仍由原检查点保存。该改动没有改变 INTERCONNECT 的数值选择、MIPD 更新策略、全局 tick 或波形可观察范围。

验证包含两平台完整回归、五组实际生成程序的 generic/compact 完整 stdout 与 ordered/settled VCD/DWF 对照，覆盖扇出、窄脉冲、输入输出串联、多驱动及 IOPATH/HOLD 组合。延迟驱动内核复用于 compact 的 Active/NBA、四态、取消、别名和预测恢复；实际生成的组合回滚程序执行 ASan/UBSan 并核对完整波形。

真实原始 SDF 程序逐字核对只有注册函数及接收端创建的预期变化。真实零延迟和 100k FF 反馈程序经实际新旧编译器生成，再由同机 C++ 预处理后逐字相同。性能必须使用独立的完整 SDF 配对数据，不能把旧零延迟结果作为此改动的收益。

本批采用结论、原始运行与核对入口见 [验收记录](../validation/m5-compact-inputs/README.md)。普通 Verilog 的自动分区执行、自动预测器及完整负检查模式仍需继续实现。
