# 单驱动重复写入候选的等价条件

状态：**已评估，未采用**。正确性通过，但真实设计的五次配对复测均变慢，已恢复原运行时。保留下面的等价条件、候选源和独立行为回归，不计入性能收益。源/结果见 [本批验证](../validation/m5-redundant-drive/README.md)。

`Sim::drive` 的原有行为为：按 signal 宽度归一化请求，保存该身份的驱动值，完成尚未定型的连接，再解析本地或 alias 组；解析值变化时触发等待、波形与并行观察者。`set` 不更新驱动表，因此驱动表与当前 signal 值可能暂时不同。

候选只在以下条件同时成立时返回：

1. 连接已经定型，缓存的 alias 成员资格有效。
2. signal 不在 alias 组中，不会因本次解析更新其他节点。
3. 已存在同一驱动身份，且不存在溢出驱动表；首次调用和新增身份均不命中。
4. 保存的驱动值等于归一化请求，原驱动赋值不会改变状态。
5. 当前 signal 值也等于请求。由于只有一个本地驱动，原解析结果就是请求值；原 `set` 也会因值未变而返回。

因此命中时原路径既不改变驱动表，也不改变 signal、watch、Active/NBA/定时队列，不产生波形或并行通知；候选只删除不可观察的重复工作。单独比较解析值不够：例如两个驱动 0/1 解析为 X，将其中一个改为 X 后解析仍是 X，但另一个释放为 Z 时必须保留这个驱动更新。单独比较驱动值也不够：直接 `set` 或 NBA 可能已改写 signal，下一次重复 drive 应恢复解析结果。

四态按完整 `a/b/width` 比较，不将 X/Z 简化为 Boolean；宽度归一化在比较前进行。所有未命中的请求继续执行原驱动登记、连接定型与解析路径。没有新增缓存字段，也没有改变 DriverValues/Signal 的布局、深复制协议、set 的唤醒规则或门级进程顺序。

延时驱动事件最终仍调用 `drive`。提前返回要求当前值与该驱动均不变，因此不能取消或重排已排队事件，也不代替路径/脉冲策略。检查点恢复同一组原始状态后，条件判断仍适用；预测事务没有新增外部效果。并行中每个 Sim 仍由单一 worker 拥有，没有新增共享缓存。

新增测试同样在冻结的原版运行时上通过，覆盖四态、1/7/64 位、独立逐位多驱动模型、直接 set/NBA 修复、驱动身份、别名、回滚、延时事务及通知序列。完整回归、有序流、生成回滚、sanitizer 和同核性能结果决定是否采用，不从等价证明推断 CPU 收益。

首轮真实设计 CPU 中位数 14.32→13.67s，但同二进制、同 CPU 五次交替配对复测变为 13.25→14.41s（增加 8.75%），五对均慢。RTL fanout 两轮分别为 2.78→2.81s、2.75→2.81s。共享主机未独占或锁频，不能仅据这些结果确定微架构原因；它们足以否定本候选已取得可复现收益的结论。后续优先检查标量四态值传递和驱动解析本身的成本，避免在所有驱动上增加未经验证的条件判断。
