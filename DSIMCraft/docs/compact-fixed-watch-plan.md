# 固定门级监听的紧凑表示候选

本轮筛选结束，三种候选均未采用。完整记录见 `validation/m5-fixed-watches`，默认 runtime 保持已验收版本。

当前每条 Watch 为16字节，含 process、edge mask、generation。compiled fixed wait 的 API 已保证 lifetime sensitivity 不变、generation 始终0；大多数门级模型使用 any-edge 监听。候选对这种列表仅保存有序 process ID，值变化时保留原来的 waiting / queued 状态转换和 FIFO 入队，不融合求值或删除事件。

动态监听或指定边沿的固定监听首次加入该列表时，将全部旧 ID 原序转换为 `{process,4,0}` 的普通 Watch，保留重复项和稳定 slot 下标。此后始终使用通用表示。状态拥有两个容器，检查点深复制实际表示及动态索引映射；恢复首次转换前的检查点必须移除后加的动态 slot。普通 RTL / 普通 Signal 继续使用原 Watch。

表示改变使紧凑 net 槽从48字节增为56字节，但纯固定监听元素从16字节减为4字节。另测64字节槽的对齐和索引成本。筛选预先声明四组：原版48、压缩56、压缩64、仅对齐64；同一完整真实设计128 golden及100k反馈，O2同编译器、同核、预热后五轮轮换。至少3%真实配对收益、五对中至少四对变快、反馈中位数回退≤3%才合格。合格项先按真实收益选取，收益差在1个百分点内优先较低RSS；胜出项还要独立七对真实/五对反馈复测，通过后才能进入默认实现。

已在56字节隔离副本通过本地38项，包括新增的转换前后快照、重复注册顺序、动态slot失效、回滚/提交、别名与额外驱动。若选择64字节，需针对最终表示重新验证。采用前还须同源Linux全回归、实际生成波形/回滚与sanitizer，并确认普通RTL预处理不变。SDF时序、波形可见点和多驱动的实际事件序列都要保留。

## 筛选结果

五轮真实设计配对 CPU 收益中位数：压缩56为6.04%，压缩64为6.18%，仅对齐64为5.08%；100k触发器反馈分别回退8.06%、11.52%、11.35%。三组均超过预先声明的反馈回退3%上限，因此不进入独立复测或默认实现。全部预热、五轮轮换、128组完整golden、源/二进制与原始time/stdout/stderr保留；没有新的VCS性能运行。

56字节候选另通过实际CLI生成的8级SDF内部连线测试：在延时事件未完成时首次加入动态监听，失败预测跨越首次表示转换；恢复后完整ordered/settled波形及观察进程状态与未压缩基线一致。此项为隔离候选验证，不把64字节两组称为已通过全功能验证，也不把功能通过当作性能采用理由。

下一候选应先消除容器与网槽扩张：固定与通用监听使用互斥存储，争取保持原48字节槽，再重新筛选组合与时序负载。仍须保留重复项、slot索引、四态边沿、动态generation与检查点深复制，不能通过少执行事件掩盖回退。
