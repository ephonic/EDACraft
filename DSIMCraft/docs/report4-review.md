# REPORT4 复核结论

读取本地 `~/vibe-coding/dsim-test/rtl-tests/complex/REPORT4.md` 及原始探针；用户指定的远端目录本次仍不存在。报告原文不改写。复测从实际稳定入口编译，不使用测试目录里遗留的可执行文件。二进制和输入哈希见 [验收记录](../validation/m94-report4/README.md)。

| 报告项 | 当前入口实测与处理 |
| --- | --- |
| p21/p27：三元分支内 `>>> / %` 符号性丢失 | 两份原始源码在 dsim 和 VCS W-2024.09_Full64 输出相同，全部可比较物理位的完整时间线相同。这里是无符号分支传播类型上下文；探针自带的 `BUG` / `bug confirmed` 文本不是仿真器诊断。保留正确语义，加入原探针和带独立检查的类型边界回归。 |
| 字符串字面量与整数混合运算 | M93 已修复。当前稳定入口通过算术、混合拼接、参数常量求值、136 位字面量、函数实参、四态条件合并和 `$bits`；与 VCS 同源输出及完整数值波形一致。 |

例如 `a=32'hfffffffe`、`b=3`、`sel=1` 时：

| 表达式 | 32 位结果 |
| --- | --- |
| `sel ? ($signed(a) >>> 1) : 32'd0` | `7fffffff` |
| `sel ? ($signed(a) / $signed(b)) : 32'd0` | `55555554` |
| `sel ? ($signed(a) % $signed(b)) : 32'd0` | `00000002` |
| 上面三式的另一个分支改为 `32'sd0` | 分别为 `ffffffff`、`00000000`、`fffffffe` |

如果测试本意是有符号运算，可将两个分支都声明为有符号类型；也可用 `$signed($signed(a) >>> sh)` 这类外层转换隔开上下文，或在函数内先完成运算。仅给整个三元表达式的结果加 `$signed`，不能恢复已经按无符号类型执行的除法/移位。新增模型还覆盖这些边界、32/64 位上下文、负除数、X/Z 条件、含 X 的操作数及除零。

例如 `"AB"+1` 得到 `32'h4143`，`{"A",8'h42}` 得到 `16'h4142`。这是字面量的 packed 数值语义；动态字符串的完整整数隐式转换仍有边界，详见 [字符串支持范围](strings.md)。

本轮没有发现需要改动编译器的新差异。新增回归和复核文档，保留与 VCS 一致的类型上下文传播。报告的两项清单不代表完整 VCS 功能差距；稳定入口沿用已发布的 M93 实现。
